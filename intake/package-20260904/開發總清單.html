壹Schema 先行

貳排除做成政策層

機台帳號對既有功能的排除，一律呼叫集中且可逐項解除的政策層（開發包⑥），不得在各功能內硬編碼帳號類型判斷——排除是現階段決策，未來會逐項恢復。

參場館範圍跟隨站台切換

後台各頁皆有頁面標題下方的站台切換下拉，一次僅顯示所選站台的資料。任何頁面都不另設「場館」篩選欄位，列表也不重複顯示場館名稱。

肆幣別與門檻都不要寫死

幣別依主站台核心貨幣（線上 USDT、機台 TWD），清單須可擴充；洗分門檻一律採機台隨請求送上的 throshold，後台不設門檻欄位。兩者都不得硬編碼。

包 ③機台金流與場次純後端・最難・schema 地基

spec 機台金流與場次_spec_v01.md（無 proto；機台端畫面由廠商實作）

  • 四支對接 API：開分 req-keyin、洗分 req-keyout（單階段）；入金 req-cashin → end-cashin、出金 req-cashout → end-cashout（兩階段，憑交易編號冪等）。憑證以 Authorization: Bearer <JWT> 附帶
  • PENDING 收斂：入金 24 小時自動轉「已逾時」（逾時後再收 end-cashin 回 1-NO RECORD）；出金不設逾時——保留至完成、被新出金取代、人工出金連動取消或 Admin 手動取消
  • 金額計算：門檻一律採洗分請求隨附的 throshold（後台不設門檻）、throshold=0＝洗出全部餘額、核可金額無條件捨去、餘數留在帳號不清除；出金一律清空餘額、不套門檻；幣別與核心貨幣不符即拒絕
  • 額度上限：判定與預留都在 req-cashin，於場館鎖內逐筆序列化，基準含已預留未入帳的入金金額；end-cashin 不再判定額度。超限回 1-OVER LIMIT、不建 PENDING、機台直接退鈔（不涉及退現）。預留於入帳轉正、PENDING 逾時（24 小時）排程關閉、Admin／站長手動取消三種情況釋放——預留與釋放必須成對（見包⑦第七節）
  • 餘額不足不寫入交易紀錄：洗分可洗金額為 0 或出金餘額為 0，僅回 1-NO CREDITS，不留紀錄（見包⑦第五節）
  • 稽核：開分／入金依 TWD 稽核倍數寫入稽核明細，預設 0 倍（倍數>0 時洗分／出金核可金額先扣未完成稽核）
  • 場次引擎：開分／入金使分數 0→正即開場；任一筆洗分／出金完成當下即結束當場（餘數立即開新場承接）；歸零結束、逾時結束、日結強制結束（餘額轉隔日期初）；同機台僅一進行中場次。有效投注額與損益以主站台核心貨幣計算
  • 前台顯示隔離：機台前台注單與遊戲紀錄僅顯示當前進行中場次
  • 單階段防重複＝不做：開分／洗分每筆一律當新交易（廠商定案：無 TX 欄位、不自動重送），以現場 SOP 因應——不要自作主張加冪等機制

相依：包②場館設定值、包①機台憑證。第一週先定案交易與場次 schema 並知會 ④⑤。

風險提示：開分無任何自然防護（重按幾次加幾次，僅受額度上限限制），為最高風險項；務必確保每筆交易在後台可查、可辨識，支撐現場「先查後台再重做」的 SOP。

包 ⑦機台功能更新新增

spec 機台更新包_spec_v01.md　proto proto/機台更新包_proto_v01.html（另附 proto/會員列表_proto_v01.html，多幣別展開已實作）

  • 一、多幣別錢包展開顯示：會員列表／側邊面板／詳細頁的餘額欄，站台啟用一種以上幣別時可展開逐列檢視。幣別清單來自鏈上錢包管理已啟用幣種；收合值＝核心貨幣錢包餘額（不換算、非加總）；機台場館僅 TWD、不顯示箭頭，但實作不得把單一幣別寫死
  • 二、存款／提款累計欄位：四欄僅計系統入出金、不含人工入出金；機台開分／入金於交易完成當下計入存款，機台洗分／出金於核實當下計入提款（待核實不計、已作廢永不計）；金額以核心貨幣原值累計、不換算 USDT
  • 三、機台憑證（JWT）：一次性顯示須允許換行完整顯示＋複製鈕；重置即失效必須由平台端比對現行憑證識別（jti／版本號）保證，只驗簽章不符合規格；不設有效期限
  • 四、場館設定的洗分門檻：後台不設門檻欄位；平台一律採請求中的 throshold（0＝全洗、規格外值回 6-BAD DATA/FORMAT）；餘數留在機台帳號；出金一律清空餘額
  • 五、交易紀錄的兩項欄位規則：場次編號欄位線上帳號顯示「—」；餘額不足不寫入交易紀錄，僅回 1-NO CREDITS
  • 六、場館日結報表：場次數的兩種算法；有效投注額與損益以核心貨幣計算
  • 七、入金額度上限的判定與預留（純後端）：req-cashin 取場館鎖判定並預留金額（基準含已預留未入帳的入金），end-cashin 不再判定；超額在紙鈔進錢箱前就被擋下。預留於入帳／逾時／手動取消時釋放

本包七節分別掛在①②③④⑤：一～三給領①的人，四給②③，五給③④，六給⑤，七給③。不需另開一組人。

已定案事項（開發時不要重新設計）

事項定案內容
洗分門檻於機台端設定（同場館各機台可不同），平台一律採請求隨附的 throshold；後台不設門檻欄位、前台不顯示門檻
出金金額一律清空餘額、不套門檻、無餘數；req-cashout 金額必為機台當前顯示的全部餘額
餘數保留洗分不足一個門檻單位的餘數留在機台帳號、不清除、不另記交易（四種金流，無「洗分餘額」類型）
餘額不足不寫入交易紀錄，僅回 1-NO CREDITS；交易狀態「未成立」不含餘額不足
機台憑證格式為 JWT、以 Bearer 附帶；重置即失效由平台端比對現行憑證識別保證（不能只驗簽章）；不設有效期限，僅靠重置使舊憑證失效
額度上限判定判定與預留都在 req-cashin，場館鎖內逐筆序列化，基準含已預留未入帳金額；end-cashin 不再判定。超限回 1-OVER LIMIT、機台直接退鈔，不涉及退現。預留於入帳／逾時（24 小時）／手動取消時釋放
核心貨幣主站台層級設定、子站台一律繼承；建立後不可修改，比照站台類型永久鎖定、編輯視窗唯讀
計價幣別有效投注額、損益、存提款累計金額一律以主站台核心貨幣原值計算，不換算 USDT
存提款累計會員列表四欄僅計系統入出金；機台開分／入金完成即計，機台洗分／出金核實後才計，人工入出金一律不計
單階段防重複廠商無法加唯一識別碼（API 已上線）、機台不會自動重送——每筆開分／洗分一律當新交易，現場 SOP（先查後台再重做）為正式因應，不做系統冪等
場次切分首要目的是前台注單顯示隔離；任一筆洗分／出金完成當下即結束場次、餘數立即開新場承接；場次不得作為風控／優惠／分潤依據
場次數依機台明細＝該機台當日場次數；依場館彙總＝該場館所有機台帳號當日場次數加總
交易保留入金 24 小時逾時；出金不設逾時（收據永久有效，交易不先於收據關閉）
過渡期收據機台暫無印表機——出金由前台自行完成兩階段，結算結果畫面拍照代收據
場館範圍跟隨頁面標題下方的站台切換下拉（後台各頁皆有）；不設場館篩選欄位、列表不顯示場館名稱
排除規則現階段營運決策、未來可逐項恢復——實作為集中政策層，禁止散落硬編碼
機台稽核目前不啟用（TWD 稽核倍數預設 0）；「開分招待」為未來活動需求，現行機制無法表達，屆時另案設計，本次不實作（已定案）
前台註冊線上站台維持開放（強制綁信箱）；機台場館前台維持不開放註冊，帳號一律由後台建立（已定案）
機台識別不另設機台編號，一律以機台帳號的會員編號識別；機台名稱＝會員暱稱（同一欄位）；一帳號綁一機台；機台與帳號不可刪除，報廢以停用處理
時區後台所有時間一律 UTC+0 顯示（含日結時間設定值）
