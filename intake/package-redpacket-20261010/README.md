## 本版新增（v02）

以下皆已寫入 `紅包_spec_v02.md`，括號內為 QA 單號。

**業務規則**

- **機台入帳場次**（019）：紅包入帳歸屬**入帳當下**進行中的場次；無場次時建立新場次（v01 已定）。紅包明細的「場次編號」仍記產生當下的場次，僅供追溯
- **機台啟用方式**（020）：隨版本對所有機台場館一次上線，不設場館開關；場館建立紅包活動即參加
- **人工出金與待確認**（022）：櫃檯人工出金視同出金，作廢待開啟紅包；人工入金不影響；出金停在「待確認」期間紅包不可開啟，被取消、取代或未成立即恢復
- **機台稽核扣除**（023）：帳號有未完成稽核（含紅包）即扣減洗分／出金核可金額，**不再以出金設定 TWD 倍數大於 0 為前提**——開發包③需配合修改
- **各站台獨立**（011）：主站台與子站台各自判斷時段重疊，活動不涵蓋子站台會員
- **幣種換算**（003）：換算為核心貨幣後四捨五入至小數 2 位再計入累計
- **數值精度**（002）：門檻、金額、機率、預算、稽核倍數最多 1 位小數；稽核倍數可為 0、不設上限

**後台畫面**

- **活動狀態**（009）：排程列表狀態欄——排程中／進行中／已結束／已取消；已結束與已取消仍列出，「取消排程」「追加預算」僅於排程中、進行中顯示
- **追加預算**（008、010）：新預算不大於目前預算時確認鈕停用並提示，後端同樣拒絕；每次追加寫入 7.4 操作紀錄
- **表單驗證**（001）：前端逐欄紅框與提示、儲存時整體檢查並捲至第一個錯誤欄位；後端同樣驗證並拒絕；提示文字見 spec 業務規則「驗證回應」
- **顯示格式**（012、013）：試算金額 2 位小數並去尾 0、成本占比 % 取 2 位；差異百分比 1 位小數、正值加「+」，相等灰色
- **匯出 CSV**（014）：欄位與順序同列表、時間 UTC+0 `YYYY-MM-DD HH:mm:ss`、不含總計列
- **權限**（015、016、017、018）：線上明細／匯出／取消排程與新增同權限；機台操作員可進列表與明細、唯讀可匯出；越權一律回「無權限」

**報表連動**（寫在 spec「對既有章節的影響」）

- **4.1 機台視角**（007）：交易類型新增「紅包」，交易狀態「已完成」、核實狀態「不適用」；4.4 機台紅包列單位 TWD
- **場館日結報表**（025）：「紅包金額」欄位於「有效投注額」之後、「損益」之前，列入總計列與 CSV；依場次明細為該場次入帳的紅包合計

**前台**（詳見 `前台調整清單.md`）

- 累計進度改為「距下一個紅包」（024）、未達標時金額一律加「最高」（固定與隨機皆同）、「本期已獲得」、開啟按鈕顯示待開啟數且一次開一個、總獎池（未設「不限」、用罄「獎池已發完」）、重置前 1 小時提示（024）
- 機台結算／洗分時的未開啟提示改為可取消的確認視窗（021）
- 紅包圖示與視窗**線上與機台共用**：達標時右側紅包圖示亮起、**不自動彈窗**（機台原「當局結束後彈出」取消），活動結束即移除圖示；有待開啟紅包時視窗顯示已抽定的實際金額、進度滿格，全部領完才回到距下一個紅包的進度；領取前經確認領取視窗；活動時間為距結束的倒數（一律 HH:MM:SS，永久顯示「永久」）、重置時間（不重置顯示「不重置」，時區沿用前台既有優惠活動）；稽核倍數為 0 時不顯示；會員等級不參加時不顯示活動（仍有待開啟紅包時照常顯示）

## 重點規則

- 累計基準：有效流水貢獻（有效投注額 × 遊戲貢獻系數），以注單結算時點計入
- 活動幣種可複選；非核心貨幣注單於**結算當下**依系統匯率換算為核心貨幣（四捨五入至 2 位）後累計，換算後不重算；門檻、紅包金額、預算、派發一律為核心貨幣
- 參加資格與門檻／獎勵依會員當下等級適用的規則（預設規則＋等級規則）
- 金額於紅包**產生當下**抽定（固定金額或權重表）；開啟即入帳，不經優惠彩金審核
- 活動總預算選填；預算占用＝已入帳＋待開啟，用罄即停止產生紅包，只能追加調高
- 機台：紅包屬於機台（帳號層級累計）、達標即時於機台畫面彈出、洗分／出金（含人工出金）完成時作廢未開啟紅包、洗分／出金進行中不可開啟、重置於場館日結時間切分
- 機台參與紅包須經排除規則政策層處理，**不得在紅包功能內硬編碼帳號類型判斷**
