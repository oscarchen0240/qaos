# 紅利幣別改動 — QA 測試整理總表

> 整合來源：《17 給QA的說明》《18 紅利幣別盤點》《20 紅利調整說明》
> 整理目的：供測試時查閱重點與細節，不遺漏例外情況

---

## 0. 三份文件的關係

- **17**：講最底層的改動 —— 系統記帳幣別從「全平台寫死 USDT」改成「每個站台自己決定」。這是因果的起點。
- **18**：在「每站有自己的核心貨幣」這個前提下，盤點「各種紅利到底發什麼幣別」，並指出幣別不一致時會出的問題（但這次不修）。
- **20**：這次版本**實際修改**的兩件事（存款金額拆分、簽到有效會員改表），以及明確的可測/不可測範圍。

三份合起來看：17 是背景架構、18 是全面盤點（含尚未修的坑）、20 是本次實際要驗收的異動。**測試時最需要緊盯的是 20 的內容**，17、18 是理解「為什麼會這樣、還有哪些已知但不動的坑」的背景知識。

## 1. 背景：系統記帳幣別改為「每站自訂」（來自 17）

### 1.1 一句話

- 以前：全系統記帳幣別寫死 `USDT`（常數）。
- 現在：每個站台在 `site_info.core_currency` 存自己的核心貨幣，**開站時決定，開站後不可改**。
- 第一個用 TWD 的站台類型：**機台站台**（實體機台場館）。
- **所有現有的線上站台維持 USDT，這次改動不影響它們的行為。**

### 1.2 改之前 vs 改之後對照

| 項目 | 之前 | 之後 |
|---|---|---|
| 系統幣別（記帳基準） | 全域常數 `"USDT"`，全平台一種 | 每個站台一個值，查站台設定取得 |
| 誰決定 | 寫死在程式裡 | 主站台開站時選定，子站台一律繼承主站台 |
| 可以改嗎 | — | **不行**。站台底下一出現會員就鎖死，且有 DB trigger 擋直接 `UPDATE` |
| 線上站台 | USDT | USDT（不變） |
| 機台站台 | 不存在 | TWD |

系統幣別是**平台記帳的基準**：報表、發紅利、算流水都用這個單位。

**限制**：站台的系統幣別必須是「啟用中的錢包幣別」之一（`wallet_currency.enabled = 1`），否則獎勵會發到玩家看不到的錢包。
⚠️ 這只保證獎勵「看得到」，**不保證幣別「唯一」**（見 1.3 機台 vs 線上的差異）。

### 1.3 機台站台 vs 線上站台（差異很大，測試時要分開看）

| 項目 | 線上站台 | 機台站台 |
|---|---|---|
| 系統幣別 | `USDT` | `TWD` |
| 玩家可以有幾種錢包 | **可同時有多種**（USDT／USD／TWD…） | **只有 TWD 一種** |
| 錢怎麼進來 | 鏈上儲值、金流通道 | **開分**（店員收現金加分）、**入金**（玩家投紙鈔） |
| 前台資產列表 | 列出所有啟用中的幣別 | **只列 TWD**（本次改動項目之一，見 1.4 第 8 項） |
| 後台鏈上錢包管理 | 完整 | **僅顯示法幣 TWD 頁籤，區塊鏈頁籤隱藏** |
| 前台註冊 | 開放 | **暫不開放自行註冊** |

**兩件事要分清楚（容易誤解的地方）**：

1. 機台站台只有 TWD，**不是程式限制**，是它根本沒有多幣別的進錢管道（現場收現金只可能是 TWD）。
2. 線上站台的多錢包**完全保留** —— 這次沒有動存款幣別，線上玩家照樣可以持有非 USDT 的餘額。

⚠️ **「站台的系統幣別是 X」不等於「玩家只能持有 X」**：
- 線上站台系統幣別是 USDT，玩家仍可同時持有其他幣別餘額。
- 機台站台看起來「只有 TWD」是進錢方式決定的，不是這次新加的限制。

### 1.4 實際被改到的 8 大類地方（原本 21 處寫死 USDT / `wallet_currency_id = 1`）

| # | 功能 | 改了什麼 |
|---|---|---|
| 1 | 發獎勵 | 返水、簽到（v1/v2）、代理、推薦、推薦註冊金、累積入金、活動 —— 錢改進「站台核心貨幣」的錢包 |
| 2 | 注單三層金額 | `game_bet_log` → `..._wallet_reference` → `..._system_wallet_reference`，第三層幣別與換算改依站台核心貨幣 |
| 3 | 後台查詢 | 注單列表與明細、返水明細、營運日報、會員列表、Dashboard 總會員數 —— JOIN 條件原本比對常數，改查站台 |
| 4 | 開站流程 | 建站時寫入核心貨幣、新增「可選幣別清單」端點、站台查詢多回一個 `coreCurrency` 欄位 |
| 5 | 新玩家註冊 | 初始錢包與顯示幣別改由站台核心貨幣推導（原本寫死幣別 id） |
| 6 | 人工出入金 | 四支原本沒有明確寫入幣別（靠 DB DEFAULT 或寫死 USDT）的 API，改成取核心貨幣 |
| 7 | 擋阻檢查 | 搬站／改站台類型不得讓幣別與站台脫節、子站台幣別必須與主站台相同、核心貨幣必須是啟用的幣別 |
| 8 | 機台站台資產列表 | 只列核心貨幣，不再列出一排餘額 0 的其他幣別 |

## 2. 各類紅利發放幣別盤點（來自 18）

### 2.1 一句話

**除了「彩金活動」與「遊戲商 JACKPOT／促銷派彩」，其他紅利一律發「站台系統幣別」。**
玩家拿哪個錢包下注、用什麼幣別存款，都不影響紅利發出來的幣別。

### 2.2 逐項對照

| 紅利 | 發放幣別 | 說明 |
|---|---|---|
| 返水 | 站台系統幣別 | 計算基礎（有效投注）本來就已換算成系統幣別，兩邊一致 |
| 代理佣金 | 站台系統幣別 | — |
| 推薦獎勵、推薦註冊金 | 站台系統幣別 | 註冊金進「收款人所屬站台」的幣別 |
| 每日簽到、累積簽到 | 站台系統幣別 | ⚠️ 簽到的**道具獎勵不是錢**，不進錢包、沒有幣別 |
| 首存／次存活動 | 站台系統幣別 | ⚠️ 活動設定裡的「幣種」是**選這個活動吃哪一條金流通道**，不是選發放幣別 |
| 累積存款活動 | 站台系統幣別 | — |
| **彩金活動** | **後台建活動時自己填的幣別** | **全站唯一可以自己選發放幣別的紅利**（2026-09-02 與 PM 確認：依後台建活動時選的幣別，送進玩家對應幣別的錢包） |
| 遊戲商 JACKPOT／促銷派彩 | **玩家該筆遊戲的錢包幣別** | 由遊戲幣別依匯率換算後入帳（PP、AWC、SABA 等） |

**測試提醒**：只有「彩金活動」和「遊戲商 JACKPOT/促銷派彩」這兩項例外，其餘全部發站台系統幣別，測試時可用來快速判斷預期結果是否正確。

### 2.3 人工存款（不算紅利，但常被混淆）

**人工存款不會進任何活動與累積統計。它只做兩件事：把錢加進錢包、寫一筆交易紀錄。**

| 項目 | 有沒有影響 |
|---|---|
| 錢進玩家錢包 | ✅ 有。後台可指定幣別，沒指定就用站台系統幣別；玩家原本沒有該幣別錢包也會自動出現一列 |
| 稽核流水（打碼量） | ✅ 有，依後台填的稽核倍數 |
| 首存／次存活動 | ❌ 不觸發，不算首儲、不會配到任何存款活動 |
| 累積存款活動 | ❌ 不累積 |
| 簽到活動的「有效會員」門檻 | ❌ 不計入 |
| 玩家累積儲值統計（VIP 等級依據） | ❌ 不計入，也不會推進 VIP 等級 |

> 2026-09-02 確認：後台人工存款目前走 **v4**，不計入累積儲值，對 VIP 等級也沒有影響。舊版 v1 API 還在線上（會計入），但後台沒有在用。

### 2.4 存款通道幣別與站台系統幣別不一致時的問題（已知但**這次不修**）

**一致時（例如機台站台系統幣別 TWD、機台通道也是 TWD）→ 全部正確。**

**不一致時**（例如 USDT 站台收到一筆 1000 TWD 的存款）：

| 經過哪裡 | 結果 |
|---|---|
| 錢進玩家錢包 | ✅ 正確，進 TWD 錢包，玩家切換錢包看得到 |
| 累積存款活動的門檻 | ❌ 1000 TWD 被當成 1000 USDT 累加，門檻提早達標 |
| 簽到活動的「有效會員」門檻 | ❌ 同上，玩家提早變成有效會員 |
| 玩家累積存款統計（VIP、排行榜） | ❌ 同上，數字被灌大 |
| 首存／次存活動 | ❌ 沒建該通道的活動就完全不發；建了活動則金額被灌大 |
| 後台營運日報總入金 | ✅ 只算系統幣別的存款，數字變小是**預期行為，不是 bug** |
| 後台人工存款 | ✅ 完全不觸發上面這些問題，打任何幣別都不會有問題 |

> ⚠️ 上面四個 ❌ 只有在「真的有一筆非系統幣別的存款進來」時才會發生。

**為什麼這次不修**：目前還沒有非系統幣別的存款會實際進來（機台的開分／入金要等實體機台交易上線；線上站台也不會用非系統幣別通道存款），現在動它得引進匯率換算，等於在沒有實際案例時多開一個出錯點。**等 TWD 存款正式進來後再一併評估調整。**

**若之後真的要修，不是「加個匯率換算」就好**：

| 問題 | 只加匯率換算夠不夠 |
|---|---|
| 首存／次存活動發放金額 | ✅ 夠，通道幣別換成核心貨幣即可 |
| 累積存款活動門檻 | ❌ 不夠，是「每筆存款累加」欄位，要決定用哪個時點的匯率，且換算後的值要存下來，否則之後對不了帳 |
| 玩家累積存款統計（VIP） | ❌ 同上，且這張表已有歷史值 |
| 簽到「有效會員」門檻 | ❌ 不夠，直接在 SQL 跑總和，沒有幣別欄位可濾、也沒有換算後欄位可加總，要加欄位或改成只算核心貨幣的存款 |

還會帶進新問題：門檻的幣別語意要先定案（活動是 per 通道建的，欄位沒標幣別）、報表口徑要一起改。**真的要做是「換算時點 → 存欄位 → 匯率 0 防線 → 後台 UI 標幣別 → 報表口徑」五件事一起做的專案**，不是加一行換算。

> 現在這幾張累加表還是乾淨的（沒有非核心貨幣存款進來過），所以現在不改，之後改不用清歷史混幣資料；但等 TWD 存款開始進來後才改，就得先清一次。

### 2.5 2026-09-02 與 PM 確認：存款活動只能發核心貨幣

以現在結構，**存款活動的獎勵只能發站台核心貨幣**，活動本身也要用核心貨幣訂門檻（例如「存 100 USD 送 30 USD」）。玩家用 TWD 存款時，理論上要換算成核心貨幣再比門檻（以 TWD:USD = 30:1 為例）：

| 玩家存入 | 換算成 USD | 結果 |
|---|---|---|
| 2100 TWD | 70 USD | 未達 100 USD，拿不到優惠 |
| 3000 TWD | 100 USD | 達標，送 30 USD |

⚠️ **現行程式還沒有這段換算**：目前直接拿存款金額的數字去比門檻，所以現況是「存 2100 TWD 也算達標、一樣送 30」。**這個落差等 TWD 存款通道進來時才一併調整，這次不修。**

## 3. 本次版本實際修改的內容（來自 20，建立日期 2026-09-08）——**測試重點**

### 3.1 一句話

**這次只改兩件事**：
1. 存款金額在「比活動門檻」和「進玩家錢包」時**分開算**。
2. 簽到活動的有效會員**改讀正確的資料表**。

⚠️ **現有站台的所有數字應該完全不變**（除了下面 3.3 標注「預期會變」的部分）。如果有其他數字變了，就是 bug。

### 3.2 改動細節

#### ① 存款金額拆成兩個欄位

以前存款金額只有一個數字，同時拿去「比活動門檻」和「進玩家錢包」。現在拆成兩個：

| 欄位 | 是什麼 | 用在哪 |
|---|---|---|
| **原始金額** | 玩家實際存的錢，玩家看到的幣別 | 進錢包、算流水倍數、算手續費 |
| **核心貨幣金額** | 換算成站台記帳幣別之後的數字 | 比活動門檻、累積儲值統計、有效會員 |

**為什麼要拆**：玩家在 USDT 站台存 3000 TWD，活動門檻是用 USDT 訂的（例如「存 100 USD 送 30 USD」），要拿換算後的 100 USDT 去比門檻，但錢包該收到的是 3000 TWD。以前兩者共用一個數字會出錯。

⚠️ **但目前所有存款的幣別本來就等於站台記帳幣別**（線上站台收 USDT、記帳也是 USDT），所以**這兩個數字現在是完全一樣的，實際行為不會變**。這次只是先把結構做好，為以後鋪路。

#### ② 簽到活動「有效會員」改讀正確的表

以前前台與後台讀的是**不同的兩張表**，而且都是區塊鏈服務自己維護的明細表（不但兩邊數字對不上，這兩張表本身也不齊全，只涵蓋部分鏈／部分時期）。

| | 以前 | 現在 |
|---|---|---|
| 後台判定 | 區塊鏈明細表 | `deposit_log_v2`（入帳成功的都在裡面） |
| 前台進度條 | 另一張更舊的區塊鏈表 | 同上，與後台一致 |

⚠️ **這是這次唯一會讓數字變的改動**。變化主要來自前台那條 —— 它原本讀更舊的一張表，落差最大；而且它是**每次玩家打開簽到頁就重算一次、達標就直接寫入有效會員**（後台那條要等玩家再存一筆才會重算）。

**部署後的實際影響**：玩家只要開一次簽到頁，就會用新口徑重算 —— **進度條數字會往上跳，本來就已經達標的玩家會立刻變成有效會員。** 這是修正（以前是漏算）不是錯誤，但要先讓營運知情。

### 3.3 這次能測什麼

#### ✅ 可以測

| # | 測什麼 | 怎麼看 |
|---|---|---|
| T1 | 前台進度條會動、且與後台一致 | 前台簽到頁的有效會員進度條，數字應跟後台判定的累積金額一致。以前前台永遠顯示 0 |
| T2 | 入金金額進錢包正確 | 存多少就進多少，幣別正確。**這是最重要的回歸點** |
| T3 | 流水倍數與手續費的基數正確 | 存款後「提領所需有效投注額」要以**實際存入金額**為基數算，不是別的數字 |
| T4 | 現有 USDT 站台的紅利數字完全不變 | 首儲／次儲、累積存款活動、VIP 等級、獎勵發放金額，改前改後比對應該一模一樣 |
| T5 | 每月重置仍正常 | 簽到活動若開了「有效會員每月重置」，跨月後進度應歸零重算 |

#### ❌ 這次測不了

| 測不了什麼 | 為什麼 |
|---|---|
| 幣別換算算得對不對 | **今天沒有任何存款會觸發換算** —— 線上站台只收 USDT，記帳幣別也是 USDT，幣別相同就直接跳過換算。要驗證換算，得等線上站台真的開一條 TWD（或其他非 USDT）的存款通道 |

⚠️ **所以這次測試重點是「有沒有弄壞」，不是「新功能對不對」**。新功能（換算）要等有實際通道才驗得到。

**補充限制**：
- **機台站台目前沒有任何紅利活動，不在這次測試範圍。** 上面所有項目都在**線上站台**測。
- **後台人工存款不計入紅利**（不進累積儲值、不觸發活動、不算有效會員），所以**沒辦法用人工存款打一筆 TWD 來測換算**。換算這條只能等線上站台實際開出 TWD 存款通道才驗得到。

## 4. 測試時的快速檢查清單（綜合三份文件）

- [ ] 確認現有線上站台的 `core_currency` 仍是 USDT，行為未受影響（17）
- [ ] 確認機台站台的核心貨幣為 TWD，前台資產列表只顯示 TWD（17 #8）
- [ ] 確認機台站台後台鏈上錢包管理只顯示 TWD 頁籤，區塊鏈頁籤隱藏（17）
- [ ] 各類紅利（返水、代理佣金、推薦獎勵/註冊金、簽到、首存/次存、累積存款）發放幣別 = 站台系統幣別（18）
- [ ] 彩金活動發放幣別 = 後台建活動時填的幣別（18，唯一例外）
- [ ] 遊戲商 JACKPOT／促銷派彩發放幣別 = 玩家該筆遊戲的錢包幣別（18，唯一例外）
- [ ] 人工存款：確認不觸發任何活動/累積統計/VIP 進度（18, 20）
