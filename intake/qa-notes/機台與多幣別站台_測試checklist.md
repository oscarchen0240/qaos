## Part 1｜機台站台功能（需 `/dev-login` + `/dev-cashflow` 測試工具）

### 前置準備

- [ ] 確認測試環境已開放 `/dev-login`、`/dev-cashflow`（若 404，找前端開通）
- [ ] 用測試帳號登入 `/dev-login`，**兩個步驟都需綠色**才算成功
- [ ] 準備一個機台站台（站台類型＝機台），核心貨幣應為 TWD

### 一、開站流程（開發包②站台列表）

- [ ] 新增主站台選「機台」類型，核心貨幣下拉選單**只顯示 TWD**（不出現 USDT）
- [ ] 建立後站台類型欄位**鎖定唯讀**
- [ ] 核心貨幣建立後**鎖定唯讀**，無法修改
- [ ] 新增子站台（場館）自動繼承主站台類型與核心貨幣，欄位唯讀顯示
- [ ] 機台專屬欄位（場館地址／聯絡人電話／額度上限／洗分出金最低門檻／場次逾時時間／日結時間）僅機台類型站台顯示
- [ ] 站台查詢 API response 應含 `coreCurrency` 欄位，值為 `"TWD"`

### 二、創建機台帳號（開發包①）

- [ ] 機台站台底下「創建會員帳號」出現「機台」帳號類型選項（線上站台不應出現）
- [ ] 選「機台」需填機台名稱，建立後同時產生機台資料
- [ ] 建立成功時登入帳號密碼**完整顯示一次**，關閉後不再顯示
- [ ] 機台狀態預設為「啟用」
- [ ] 會員詳細頁出現「機台資訊」「機台憑證」兩區塊
- [ ] 機台憑證可產生／重置，僅一次性完整顯示，之後前後4碼+遮罩
- [ ] 「重設密碼」對機台帳號適用，新密碼+帳號一次性完整顯示，舊密碼立即失效

### 三、機台金流四種交易（開發包③，用 `/dev-cashflow` 測試）

**開分**
- [ ] 開分成功後分數正確增加，餘額即時更新
- [ ] 超過場館額度上限應被拒絕，機台顯示失敗，分數不變（額度為全場館機台共用）
- [ ] 重複按開分會重複加分——確認為已知風險行為（無自然防護），非bug

**洗分**
- [ ] 洗分金額被場館「洗分/出金最低門檻」無條件捨去，核可金額≠填寫金額
- [ ] 全洗後不足一個門檻單位的餘數留在機台
- [ ] 洗分完成後立即出現在「洗分出金核實」頁，狀態「待核實」

**入金**
- [ ] 兩階段流程：只按①不按②，分數不變
- [ ] 按②確認後分數才正確增加
- [ ] 超過24小時未完成的入金自動轉「已逾時」

**出金**
- [ ] 出金一律全額計算，比照洗分以門檻為單位，餘數留機台
- [ ] 出金產生訂單編號，可於「洗分出金核實」用訂單編號核銷查詢
- [ ] 出金不設逾時，待確認狀態持續保留
- [ ] 出金重按第一階，前一筆應失效

### 四、場次邏輯（開發包③）

- [ ] 洗分或出金扣分成功當下即結束當前場次；有餘數立即開新場次承接
- [ ] 分數歸零視為場次結束
- [ ] 機台前台注單/遊戲紀錄僅顯示**當前進行中場次**，換人看不到前一位紀錄
- [ ] 會員詳細頁「機台資訊」正確顯示進行中場次摘要
- [ ] 場次逾時（依場館設定）正確觸發結束

### 五、機台交易紀錄查詢（開發包④）

- [ ] 篩選器（機台帳號/交易編號/場次編號/訂單編號/交易類型/交易狀態/核實狀態/交易時間/金額）皆可正常查詢
- [ ] 場館範圍跟隨站台切換，無獨立「場館」篩選欄位
- [ ] 五種交易狀態（待確認/已完成/已取消/已逾時/未成立）正確對應
- [ ] 幣別欄位顯示主站台核心貨幣（TWD）
- [ ] 核實狀態欄位**唯讀**
- [ ] Admin 可對「待確認」交易手動取消，其他角色不可

### 六、洗分出金核實（開發包⑤之一）

- [ ] 已完成的洗分/出金自動產生「待核實」紀錄
- [ ] 核實（洗分）：確認彈窗顯示機台帳號/實際金額/交易時間，確認後轉「已核實」
- [ ] 核實（出金）：可用訂單編號查詢，核實即核銷收據
- [ ] 已核實/已作廢的紀錄，再次核實應被阻擋（防重複付款）
- [ ] 核實/作廢**一經確認無法撤銷**
- [ ] 作廢僅出金可執行，僅 Admin/站長可操作，須填作廢原因
- [ ] 操作員權限限自身場館

### 七、場館日結報表（開發包⑤之二）

- [ ] 統計週期切換（按日/週/月/區間合計）數字正確彙總
- [ ] 統計維度切換（依場館彙總/依機台明細/依場次明細）正確呈現
- [ ] 「現金淨收」公式正確：開分＋進鈔－已核實洗分－已兌現（**不扣待核實洗分**）
- [ ] 「未兌現金額」正確反映截至查詢當下的待核實出金金額
- [ ] 匯出 CSV 功能正常

### 八、機台場館後台選單規則（開發包⑥）

- [ ] 站台切換到機台場館時，指定頁面正確隱藏（資訊看板/加盟列表/出金審核/優惠彩金審核/返水明細等）
- [ ] 鏈上錢包管理僅顯示法幣 TWD 頁籤，區塊鏈頁籤隱藏
- [ ] 切回線上站台選單恢復完整
- [ ] 出金設定新增的 TWD 頁籤可正確設定稽核倍數

### 九、跨站台一致性檢查

- [ ] 機台站台資產列表**只列 TWD**，不列其他餘額0的幣別
- [ ] Free Spin 派發依核心貨幣（TWD）發放，非固定 USDT
- [ ] 搬站/改站台類型導致幣別與站台脫節時，系統應阻擋

## Part 2｜線上站台多幣別測試（現有 TWD 錢包，可直接測）

### 補充可測項目

| # | 測試情境 | 預期結果 |
|---|---------|---------|
| A | 玩家用 TWD 入金 | 入金正常進 TWD 錢包，不應被導去 USDT 錢包 |
| B | 玩家用 TWD 錢包下注 | 注單能正常下注、結算，幣別維持 TWD |
| C | 注單三層金額（bet_log→wallet_reference→system_wallet_reference） | 前兩層記錄 TWD，第三層 system_wallet_reference 應換算成 USDT |
| D | 用 TWD 錢包下注後觸發返水/活動獎勵 | 獎勵應進**站台核心貨幣（USDT）錢包**，不是進 TWD 錢包 |
| E | 後台查詢（注單列表/明細） | 用 TWD 下的注單，後台能否正確顯示幣別與換算後 USDT 金額 |
| F | 前台資產列表 | 同時列出 USDT 和 TWD |

### 高風險點提醒

1. **D項（獎勵發放幣別）**：文件明確寫「錢要進到站台核心貨幣那個錢包」，容易被誤測成「應該進 TWD」
2. **C項（三層金額換算）**：TWD→USDT 換算匯率與金額落地是否正確，建議多筆不同金額交叉驗證

## Part 3｜補充測試案例（依已發現問題延伸）

### G. 注單顯示格式／篩選器換算一致性（依你已發現的兩個 bug 延伸）

| # | 測試案例 | 驗證重點 |
|---|---------|---------|
| G1 | 「注单显示格式」切換 USDT／TWD／結算幣種，同一筆 TWD 原生注單分別查看 | 投注額/有效投注額/有效流水貢獻/派彩，是否**全部欄位**都跟著換算，而非部分換算部分不換算 |
| G2 | 「投注額」篩選器，在不同「注单显示格式」下輸入相同 min/max | 驗證篩選比對的是原始幣別數字還是顯示幣別換算後數字（依已發現 bug，需回歸驗證修復狀況） |
| G3 | 「有效流水貢獻」「派彩」「貢獻系數」等其餘 min/max 範圍篩選器 | 逐一排查是否有相同的未依顯示格式換算問題 |
| G4 | 返水明細頁的類似篩選器/顯示欄位 | 是否存在跟注單查詢頁一樣的換算不一致問題（同源代碼風險） |

### H. 「以貨幣顯示」與遊戲下注幣別關聯測試

| # | 測試案例 | 驗證重點 |
|---|---------|---------|
| H1 | 固定選 USDT 錢包進場，「以货币显示」分別切 USD/TWD/EUR 後各下注一筆 | 比對 `gameCurrencySymbol` 是否隨顯示設定變動；`walletCurrencySymbol` 是否維持 USDT 不變 |
| H2 | 「使用以下余额进行游戏」彈窗，切換「以货币显示」後重新開啟彈窗 | 「所选货币将以 XXX 显示」文字是否正確同步（已知bug，回歸測試用） |
| H3 | 遊戲進行中切換「以货币显示」 | 驗證「游戏将刷新并重新启动」是否真實觸發，中途下注是否受影響/遺失 |
| H4 | TWD 顯示、USDT 錢包，實際下注輸入「20」 | 驗證 `walletBet` 扣款金額是否為 20÷匯率（USDT錢包被扣的真實金額量級是否合理，避免玩家誤解實際下注規模） |
| H5 | 派彩/贏分結果 | 驗證派彩金額幣別是否與下注時 `gameCurrencySymbol` 一致，玩家實際獲得金額是否正確入帳到 walletCurrencySymbol 錢包 |

### I. 站台核心貨幣 API 驗證

| # | 測試案例 | 驗證重點 |
|---|---------|---------|
| I1 | 站台查詢 API（站台列表/站台詳細） | response 應含 `coreCurrency` 欄位，線上站台值為 `"USDT"` |
| I2 | 「可選幣別清單」端點 | 線上站台類型只回傳 USDT；機台站台類型只回傳 TWD |
| I3 | 站台核心貨幣鎖定驗證 | 已有會員的站台，嘗試變更核心貨幣（如有UI入口）應被阻擋；直接對DB執行UPDATE應被trigger擋下（此項需協同後端測試） |

### J. 人工出入金幣別驗證（對應 QA 文件第6項「四支API」）

| # | 測試案例 | 驗證重點 |
|---|---------|---------|
| J1 | 人工存入（create-manual-deposit）未指定幣別時 | 應自動帶入站台核心貨幣，而非DB DEFAULT或寫死USDT |
| J2 | 人工提出對應API | 同上，幣別應正確取核心貨幣 |
| J3 | 人工出入金指定TWD錢包 | 驗證資金正確進出TWD錢包，不影響USDT主錢包 |
