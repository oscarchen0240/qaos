# SPEC-SITELIST-001 v0.5 增補草稿（依 PM 2026-09-14 回覆整理，待 Spec 作者合入正本後匯入）

> 來源：CLR-SITELIST-001 ~ 007 的 PM 回答。合入 `站台列表_spec_v05.md` 後，以 `bin/qaos spec import … --version 0.5` 匯入，走 WF-C 更新受影響 TC。

## 補入 §業務規則與驗證
- 子站台類型／核心貨幣繼承：**後端強制**，非僅前端唯讀限制；透過 API 帶入與主站台不同的站台類型會被拒絕。（CLR-001）
- 額度上限：輸入負數時前端顯示「值必須大於或等於 0」，**後端也拒絕**（雙層驗證）。（CLR-002）
- 場次逾時時間：**後端最低值為 1 小時**，低於此值拒絕；輸入超過 17 位數時前端跳格式錯誤，後端阻擋並回傳 `COMMON_INVALID_REQUEST_FORMAT`。（CLR-003）
- 上層站台（新增＋編輯）：站長的「固定當前層／唯讀」限制**後端已強制**，非僅前端限制；此前已知的「直接呼叫 API 仍可成功」風險已修復。（CLR-005、CLR-006）

## 補入 §操作/刪除站台（重大變更 — 已定案，見 CLR-SITELIST-009）
- CLR-007 確認：機台類型站台不提供刪除操作，只能停用。
- CLR-008／CLR-009 最終確認（2026-09-14，PM／後端共同確認）：**任何類型（含線上）皆不提供刪除操作，前端與後端皆拒絕**，只能暫停／關閉（停用）。原因是刪除站台會影響站台樹狀結構（子站台歸屬、上下層關係）。**spec.md v0.4 原文「刪除站台可正常執行、二次確認後生效」一節為錯誤敘述，非目前產品行為，待 Spec 作者合入 v0.5 時一併修正／移除該節**。
- 受影響的既有 ACTIVE TC 已先行退役（TC-SITELIST-040/041/043/044，測的是「刪除確認彈窗」「線上類型可刪除」等前提，已不成立）；TC-SITELIST-042 的擴大範圍修訂（RUN-20260914-003）依此結論重新設計並送驗證。

## 補入 §角色與權限（引用圖示，非新規則，供 TC 依據）
- 可見範圍模型：Admin 看全平台；主站台 A 的管理員/站長看 A 及其子樹；操作員只看自身場館。可指派範圍：管理員可指派管理員/站長及以下，站長只能指派站長以下，操作員不可指派。（CLR-004，與 CLR-PLATFORMRULE-001 同一張圖）
