### 功能說明

供管理員管理平台下所有子站台。每個子站台為一個獨立前台運營單位，擁有各自的網域、狀態與模板設定；站台之間可形成無限層級的父子關係。

全平台的站台構成**單一一棵樹**，樹根是系統建置的**根站台 `admin`**（代碼 `ZZ`）——所有站台皆為它的後代，不存在第二棵樹（見「根站台」）。

核心能力：

  - **站台管理：** 新增、編輯、刪除站台紀錄
  - **站台類型：** 每個站台為「線上」或「機台」二擇一，建立後不可修改；「機台」站台對應一間實體遊藝場（場館），帶場館專屬設定欄位
  - **核心貨幣：** 主站台層級的通用設定，底下所有子站台一律繼承，不可各自指定
  - **根站台：** 全平台唯一、系統建置的 `admin`，是所有站台的共同源頭；受保護，不可刪除、不可變更狀態、不可指定上層（見「根站台」）
  - **階層管理：** 站台可掛載於任意站台底下，層數不限；根站台底下的第一層即**主站台**（各客戶的頂層站台）
  - **狀態管理：** 新建站台固定為「待開通」，後續依角色權限調整狀態；網域異動時系統自動觸發「更新待審」
  - **網域管理：** 為每個站台設定前台與後台網域，支援無限新增；管理員 與站長皆可操作
  - **模板管理：** 模板由 管理員 指定；新建時可留空，切換為「開通」狀態時必須填入
  - **階層瀏覽：** 逐層點擊進入子站台列表，上方路徑列顯示當前位置
  - **權限分層：** 管理員與站長的**可見範圍相同**（自身站台及所有子站台），差別在操作深度——管理員可操作管轄範圍內的所有欄位並指派角色，站長部分欄位唯讀
  - **篩選搜尋：** 依狀態篩選、依名稱或代碼搜尋，作用於當前層

### 角色與權限

本功能區分「管理員」與「站長」兩種角色。

> ⚠️ 「管理員」**每個站台皆有**，權限範圍跟著所屬站台走（自身站台及其所有子站台），層級高於同站台的站長；手冊 v01 的角色模型（見 7.1.1 角色說明）未定義此角色，為本功能新增。根站台 `admin` 的管理員因其子樹即全平台，故等同看到全部站台——這是所屬站台的位置造成的，不是角色本身有跨站權限。

管理員與站長的**可見範圍相同**，差別在能操作到什麼深度。管理員對**子站台**有完整權限；對**自身所屬站台**則受限，見下表末三列。

| 功能項目 | 管理員 | 站長 |
| ------- | ----- | ---- |
| 可見站台範圍 | 自身站台及所有子站台（不含平行或上層站台）；根站台的管理員＝全平台 | 同左 |
| 新增子站台 | 可新增，可於管轄範圍內自由選取上層站台 | 可新增，上層站台固定為當前所在層，不可修改 |
| 子站台：上層站台（編輯） | 可於管轄範圍內自由修改 | 唯讀顯示；如需變更須通知管理員操作 |
| 子站台：模板（新增／編輯） | 可選取或修改 | 唯讀顯示；如需變更須通知管理員操作 |
| 子站台：狀態切換 | 可切換為任意狀態（含「開通」） | 僅可切換為「暫停」或「關閉」 |
| 子站台：刪除 | 可操作 | 可操作 |
| 網域新增／刪除 | 可操作 | 可操作；操作後若站台為「開通」或「更新待審」，系統自動切換為「更新待審」 |
| 角色指派 | 可在管轄範圍內指派**管理員與站長**（及以下所有角色） | 僅可分配站長以下的角色權限，不可指派管理員 |
| **自身站台：上層站台** | **不可修改**——須由上層站台的管理員操作 | 不可修改 |
| **自身站台：刪除** | **不可刪除**——須由上層站台的管理員操作 | 不可刪除 |
| **自身站台：狀態切換** | 可切「暫停」「關閉」；**不可切為「開通」**（含由「更新待審」切回）——須由上層站台的管理員操作 | 同左 |

> ⚠️ 管理員對自身站台的三項限制（上層站台、刪除、切為「開通」）是為了避免自己把自己搬走、刪掉或違規上線；其餘欄位（名稱、網域、模板、場館設定）可自行編輯。根站台 `admin` 無上層，故這三項對它一律不成立——它另有完整的保護規則（見「根站台」）。

### 站台狀態

共五種狀態（列表以 Badge 色標呈現）：

| 狀態 | 色標 | 觸發方式 | 說明 |
| ---- | ---- | ------- | ---- |
| 待開通 | 灰色 | 新建站台自動設定 | 尚未上線，模板可留空 |
| 開通 | 綠色 | **上層站台的管理員**手動切換 | 站台正常運作中；切換為此狀態時模板為必填；站台自身的管理員與站長皆不可自行切為開通 |
| 暫停 | 黃色 | 該站台的管理員或站長切換，上層站台的管理員亦可 | 站台暫停服務，可由上層站台的管理員恢復為開通 |
| 關閉 | 紅色 | 該站台的管理員或站長切換，上層站台的管理員亦可 | 站台已永久停止服務 |
| 更新待審 | 紫色 | 系統自動觸發 | 站台處於「開通」或「更新待審」狀態下，若前台或後台網域有異動，儲存後自動切換；待技術部門完成設定後由**上層站台的管理員**人工切回「開通」 |

「更新待審」為系統自動觸發，不開放手動選取；上層站台的管理員可在此狀態下手動切換為其他任意狀態。

### 站台類型與機台專屬欄位

每個站台的「站台類型」為**線上 / 機台，二擇一；建立後不可修改**。站台類型「機台」的站台對應一間實體遊藝場（以下稱**場館**）；類型為「機台」時才顯示下列機台專屬欄位。站台類型於**主站台（根站台 `admin` 底下第一層）選定**，**子站台一律與主站台同類型、不可個別選擇**——機台主站台對應一個實體遊藝場經營者，其子站台即場館；線上主站台底下皆為線上子站台。**凡機台類型站台（主站台或子站台）皆帶機台專屬欄位**：機台主站台可**自行直接經營**（自身即一間場館），也可在底下建立場館子站台；每份場館設定的**作用範圍為該站台自身、不含子站台**（額度上限、場次逾時、日結時間各站台各自一份，互不影響）。站台列表原有的新增／編輯／刪除／網域／模板操作完全不變，只是多了幾個欄位。機台專屬欄位的完整業務規則以 `實體機台_spec_v07.md` 為準。

| 欄位 | 說明 |
| ---- | ---- |
| 場館幣別 | **唯讀**，自動顯示所屬主站台的核心貨幣，不可於場館層級變更（見下方「核心貨幣」）。⚠️ 新增／編輯視窗**不另設本欄位**——與「核心貨幣」為同一個值，由核心貨幣欄的子站台唯讀繼承顯示承載，避免同值出現兩次；本欄僅用於場館設定的**檢視情境**（如機台資訊、報表） |
| 場館地址 | 選填，供對帳與稽核識別 |
| 場館聯絡人／電話 | 選填 |
| 額度上限 | **場館層級設定，該場館底下所有機台帳號共用同一份額度**——開分／入金時以「全場館機台分數餘額合計」檢核，不是每台各有一份上限；機台不個別調整；修改後即時生效，不影響既有餘額；設為 0 代表不限制 |
| 場次逾時時間 | 機台仍有餘額但無任何交易與遊玩時，自動結束場次的時間長度；**預設 1 小時**，站長可調整，操作員唯讀 |
| 日結時間 | 每日結算的截止時刻（UTC+0），用於場館日結報表分日 |

> 📖 「操作員」為實體機台功能新增的場館現場管理角色，權限小於站長，本章不另定義，詳見 `實體機台_spec_v07.md`「角色與權限」。

### 核心貨幣

「核心貨幣」是站台層級的**通用設定**，不是實體機台專屬。幣別**不在子站台（場館）層級設定，而是主站台層級的設定**：一個主站台選定一種核心貨幣，其底下所有子站台一律沿用，不可各自指定。

  - 主站台（根站台 `admin` 底下第一層）的核心貨幣為**下拉選單，選項依站台類型過濾**——可選幣別清單依類型維護，目前線上＝**USDT**、機台＝**TWD** 各僅一種，故實際上等同自動帶入（2026-08-21 客戶定案）。⚠️ **實作不得將幣別寫死**：幣別清單須可擴充，未來增加幣種只擴充清單、不改邏輯。子站台一律繼承，唯讀顯示
  - 實體遊藝場客戶的主站台核心貨幣即 **TWD**，該主站台下所有場館與機台一律以 TWD 計價與記帳，不涉及匯率換算
  - **主站台建立後，核心貨幣不可修改**（v07 定案）：比照「站台類型」，於建立時選定即永久鎖定，編輯視窗唯讀顯示；要換幣別只能另建主站台。既有餘額、注單與報表的幣別語意不會中途改變

### 根站台

全平台的站台是**單一一棵樹**，樹根為系統建置的**根站台 `admin`**（代碼 `ZZ`，站台類型「線上」）。所有站台——含各客戶的主站台——一律掛在它底下，**不存在第二個根、也不存在無上層的站台**。

| 項目 | 規則 |
| ---- | ---- |
| 數量 | 全平台**恰好一個**，由系統建置，不開放新增第二個 |
| 上層站台 | 無，且**不可指定**；新增／編輯視窗的「上層站台」欄不適用 |
| 刪除 | **不可刪除**，列表不顯示刪除按鈕；即使以 API 直接呼叫也須擋下 |
| 狀態 | **不可變更**，恆為「開通」；列表與編輯視窗的狀態欄唯讀，不可切為暫停／關閉／更新待審 |
| 站台類型／核心貨幣 | **不參與繼承鏈**——根站台自身的類型與貨幣不往下傳，類型與貨幣改由各主站台各自選定（見「站台類型與機台專屬欄位」、「核心貨幣」） |
| 可見者 | 僅**根站台自身的管理員**看得到根站台這一列；主站台以下的管理員與站長進入後台的起點都是自身所屬站台，看不到根站台，也看不到平行的其他主站台 |
| 網域／模板 | 可設定，行為與一般站台相同 |

> ⚠️ 根站台是整個平台的單一失效點——被刪除或被切為非「開通」狀態時，其下所有站台與前台皆受影響。上述保護規則須在**後端一併實作**，不能只靠前端隱藏按鈕。

### 主站台

**主站台＝根站台 `admin` 底下的第一層站台**，即一個客戶（營運方）的頂層站台，其下可再展開無限層子站台。

  - **站台類型與核心貨幣在主站台這一層選定**，其下所有子站台一律繼承、不可各自指定——機台主站台對應一個實體遊藝場經營者，其子站台即場館
  - 根站台本身**不是**主站台，其類型（線上）與貨幣不會傳給底下的主站台；因此機台類型的主站台可以直接掛在根站台底下，不受根站台為「線上」的影響
  - 站長的管轄範圍即自身所屬的主站台及其所有子站台

### 階層結構與逐層瀏覽

  - **上下層關係：** 每個站台指定一個上層站台，層數不限；唯一的例外是根站台 `admin`，它沒有上層
  - **起始層顯示：** 一律顯示**自身所屬站台**這一列，點入即為其子站台；根站台的管理員因所屬站台就是 `admin`，起始層即根站台這一列（點入為各主站台）
  - **鑽入：** 點擊任意站台名稱，進入該站台的子站台列表
  - **路徑列：** 頁面頂部顯示當前瀏覽路徑，點擊任意節點可跳回該層，點擊「站台列表」回到根層
  - **子站標示：** 站台名稱旁顯示「N 個子站」；無子站時不顯示
  - **可見範圍：** 站長僅能看到自身所屬站台及其所有子站台，不包含平行站台或上層站台

### 操作

**新增站台**

點擊右上角「+ 新增站台」開啟 Modal，欄位如下：

| 欄位名稱 | 管理員 | 站長 | 說明 |
| ------- | ----- | ---- | ---- |
| 上層站台 | 自動帶入當前所在層；可搜尋改選任意站台（搜尋結果顯示站台名稱、代碼及完整路徑）；**不可留空**——所有站台都必須有上層，唯一無上層者為系統建置的根站台 `admin` | 預帶當前所在層，唯讀不可修改 | — |
| 站台名稱 | 必填 | 必填 | 站台的顯示名稱，用於後台識別 |
| 站台代碼 | 必填 | 必填 | 兩碼大寫英文字，輸入時自動轉大寫；全系統唯一，建立後鎖定 |

### 模板設定

  - **來源：** 模板選項來自模板管理功能（另一張設定表），清單內容依系統設定動態顯示，非固定清單
  - **指定權限：** 僅管理員可指定或修改；站長的模板欄位為唯讀，如需變更須通知管理員
  - **填寫規則：** 新建站台時模板可留空；當狀態切換為「開通」時，模板為必填，否則阻擋儲存並提示錯誤

### 業務規則與驗證

| 項目 | 規則 |
| ---- | ---- |
| 站台名稱必填 | 名稱為空時阻擋儲存，輸入框標示紅框與錯誤提示 |
| 站台代碼格式 | 必須為恰好兩碼大寫英文字；輸入時自動轉大寫並過濾非英文字元 |
| 站台代碼唯一性 | 新增時檢查是否重複；重複時阻擋儲存並提示錯誤 |
| 站台代碼鎖定 | 建立後不可修改，編輯彈窗中顯示為唯讀 |
| 狀態（新增） | 不顯示狀態欄位，固定建立為「待開通」，管理員與站長皆同 |
| 狀態（站長編輯） | 僅可切換為「暫停」或「關閉」；選取其他狀態時阻擋儲存 |
| 模板（切換開通） | 狀態切換為「開通」時，模板為必填；留空則阻擋儲存並提示錯誤 |
| 模板（站長） | 站長新增與編輯時，模板欄位不顯示或唯讀，不開放修改 |
| 網域異動觸發 | 站台為「開通」或「更新待審」時，儲存若有網域新增或刪除，系統自動切為「更新待審」；適用於所有角色 |
| 上層站台（站長） | 站長新增時上層站台固定為當前層，不可修改；編輯時唯讀，如需變更須通知管理員 |
| 管理員的自身站台限制 | 管理員不可修改自身所屬站台的上層站台、不可刪除自身站台、不可將自身站台切換為「開通」（含由「更新待審」切回）；這三項須由**上層站台的管理員**執行。對子站台無此限制 |
| 角色指派範圍 | 管理員可在管轄範圍內指派管理員與站長（及以下所有角色）；站長僅可分配站長以下的角色權限，不可指派管理員（見 7.1.1 角色說明） |
| 上層站台循環防護 | 編輯時，不可將自身或自身的子站台選為上層站台 |
| 根站台唯一 | 全平台恰好一個根站台 `admin`（代碼 `ZZ`），由系統建置；不開放新增第二個根，一般站台一律須指定上層站台，「上層站台」不可留空 |
| 根站台不可刪除 | 根站台不顯示刪除按鈕，後端亦須擋下刪除請求 |
| 根站台狀態鎖定 | 根站台狀態恆為「開通」，不可切為暫停／關閉／更新待審；列表與編輯視窗唯讀 |
| 根站台不參與繼承 | 根站台的站台類型與核心貨幣不往下傳；類型與貨幣由各主站台（根站台底下第一層）各自選定，故機台主站台可直接掛在線上型的根站台底下 |
| 網域格式 | 不做格式驗證，由管理員自行確保正確性 |
| 站台類型鎖定 | 建立後不可修改，編輯彈窗中顯示為唯讀 |
| 站台類型隨主站台 | 站台類型於主站台（根站台底下第一層）選定，子站台一律與主站台同類型、不可個別選擇——機台主站台＝實體遊藝場經營者、其子站台即場館；線上主站台底下皆線上子站台 |
| 機台主站台可直接經營 | 機台主站台自身即可作為一間場館經營，帶完整場館設定；每份場館設定（額度上限、場次逾時、日結時間）的作用範圍為**該站台自身、不含子站台**，主站台與各場館各自一份、互不影響 |
| 核心貨幣依類型過濾 | 主站台核心貨幣的可選清單**依站台類型過濾**：目前線上＝USDT、機台＝TWD（各僅一種，等同自動帶入；2026-08-21 客戶定案）。實作不得寫死幣別——清單須可擴充，未來增加幣種只擴充清單、不改邏輯 |
| 核心貨幣繼承 | 子站台一律沿用所屬主站台的核心貨幣，不可各自指定；場館幣別欄位唯讀顯示繼承值 |
| 額度上限（場館） | 場館層級設定，該場館所有機台帳號共用同一份額度；設為 0 代表不限制；修改後即時生效，不影響既有餘額 |
| 洗分門檻採用值 | **後台不設門檻**（v04 起移除「洗分／出金最低門檻」欄位，2026-09-01 定案）：洗分一律以機台隨請求送上的門檻值（`throshold`）為準計算，門檻於機台端設定、同場館各機台可不同；出金一律清空餘額、不套門檻。詳見正本「業務規則」 |
| 場次逾時 | 逾時時間取自場館設定，預設 1 小時 |
| 場館站台狀態 | 場館站台（含自行經營的機台主站台）不是「開通」狀態時，該場館所有機台一律無法運作 |
| 刪除確認 | 刪除前顯示確認彈窗，列出站台名稱與代碼，二次確認後執行；操作不可復原 |
