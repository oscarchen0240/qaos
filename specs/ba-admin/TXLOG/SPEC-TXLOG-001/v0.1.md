### 功能說明

查詢所有機台的每一筆金錢進出，**包含尚未完成與被拒絕的交易**。這是現場發生爭議時（例如玩家反映「我投了錢但分數沒加」）的主要查核工具。

既有的 4.1 只顯示已經生效的錢包異動；併入後，查詢範圍含機台交易時**另外顯示尚未完成、被取消與被拒絕的交易**，並提供機台與場次視角的篩選與欄位（即本檔以下規格）。非機台交易的既有行為不變。

-----

### 篩選器

頁面資料範圍跟隨頁面標題下方的**站台切換下拉選單**（後台各頁皆有，一次僅顯示所選站台），不另設「場館」篩選欄位。

| 篩選欄位 | 類型 | 說明 |
| ------- | ---- | ---- |
| 機台帳號 | 文字輸入 | 輸入會員編號查詢；支援多筆，以「,」分隔 |
| 交易編號 | 文字輸入 | 查詢特定一筆交易 |
| 場次編號 | 文字輸入 | 查詢某個場次內的所有交易 |
| 訂單編號 | 文字輸入 | 出金專用，即收據上印製的編號 |
| 交易類型 | 下拉選單 | 全部 / 機台開分 / 機台洗分 / 機台入金 / 機台出金 |
| 交易狀態 | 下拉選單 | 全部 / 待確認 / 已完成 / 已取消 / 已逾時 / 未成立 |
| 核實狀態 | 下拉選單 | 全部 / 待核實 / 已核實 / 已作廢 / 不適用；僅對「機台洗分」與「機台出金」有意義（核實於「洗分出金核實」頁操作，本頁僅供查詢） |
| 交易時間 | 日期範圍 | 依交易發生時間篩選 |
| 金額 | 範圍輸入（min ～ max） | — |

設定後點擊「搜尋」執行，點擊「清除」重置所有條件。

### 交易狀態

| 狀態 | 說明 |
| ---- | ---- |
| 待確認 | 交易已受理，但尚未收到機台的完成回報；**分數尚未異動** |
| 已完成 | 交易完成，分數已異動 |
| 已取消 | 出金交易被新的出金請求或櫃檯人工出金取代而作廢；分數未異動 |
| 已逾時 | **僅入金會出現**：超過 24 小時仍未收到機台回報而自動關閉；分數未異動。出金不設逾時，見下方說明 |
| 未成立 | 平台拒絕了這筆請求；分數未異動，原因見「未成立原因」欄（餘額不足不寫入紀錄，故本狀態不含餘額不足） |

> ⚠️ 「待確認」代表交易卡在中間狀態——機台已經動作（例如紙鈔已收、收據已印），但平台還沒收到完成回報。若某台機台長時間累積多筆「待確認」，通常代表該機台網路或設備異常，應通知現場檢查。
>
> 入金與出金的收斂方式不同：**入金**超過 24 小時自動轉「已逾時」；**出金不設逾時**，待確認會一直保留，直到機台補完回報、被新的出金取代、櫃檯人工出金連動取消，或由 Admin 手動取消為止（收據永久有效，對應的交易不先於收據關閉）。

### 列表欄位

列表底部顯示當前篩選結果的金額總計（依交易類型分列）。

| 欄位 | 說明 |
| ---- | ---- |
| 交易編號 | 系統產生的唯一交易識別碼 |
| 訂單編號 | 出金交易顯示收據上的編號，其餘顯示「—」 |
| 場次編號 | 該筆交易所屬的場次；可點擊篩出同場次的所有交易。線上帳號的交易無場次，統一顯示「—」（2026-09-03 定案） |
| 機台帳號（來源機台） | 會員編號，可點擊進入會員詳細資料頁；非機台交易顯示「—」。**場館名稱不顯示**——場館已由頁面標題下方的站台切換限定，每列相同、屬冗餘資訊 |
| 交易類型 | 機台開分 / 機台洗分 / 機台入金 / 機台出金 |
| 幣別 | 主站台核心貨幣 |
| 請求金額 | 機台送出的金額；出金則為平台核算的可出金額 |
| 實際金額 | 實際異動的金額；洗分因門檻計算可能小於請求金額（門檻採機台隨請求送上的值，2026-09-01 定案），尚未完成者顯示「—」；出金一律為全額清空餘額 |
| 交易狀態 | 五種狀態之一，Badge 色標呈現 |
| 核實狀態 | 洗分與出金顯示「待核實／已核實／已作廢」，其餘交易類型顯示「—」；**待核實的洗分**以醒目色標提示（待核實的出金屬正常，不提示）。狀態由「洗分出金核實」頁的操作回寫，本頁唯讀 |
| 核實人員／時間 | 於「洗分出金核實」頁執行核實的後台帳號與時間（UTC+0）；待核實顯示「—」 |
| 未成立原因 | 僅「未成立」狀態顯示，內容見「交易不成立的原因」對照表（定義於開發包③／正本） |
| 交易時間 | 交易發生時間（UTC+0） |
| 完成時間 | 交易完成時間（UTC+0）；尚未完成者顯示「—」 |
| 重送次數 | 機台重複回報同一筆交易的次數；為 0 時顯示「—」 |
| 來源 | 交易發生的位置；空值顯示「大廳」 |

### 操作

  - **查看明細：** 點擊任一列開啟右側面板，顯示該筆交易的完整往來紀錄。⚠️ 面板下半部為技術欄位，供開發團隊排查用，站務人員以上半部的摘要為準即可
  - **手動取消：** 僅 Admin 可對「待確認」狀態的交易執行；二次確認後標記為「已取消」，分數不異動。用於機台故障造成的卡單清理

> 本頁**不提供核實操作**——洗分與出金的核實一律於 帳務管理 \>「洗分出金核實」執行（見該小節），本頁的核實狀態欄位僅供查帳。

> ⚠️ **手動取消前務必先與現場確認實體狀況**——紙鈔是否已進錢箱、收據是否已印出。取消後平台會告知機台這筆交易不存在，機台就會停止重試；若現場實際上已經收了錢或印了收據，會造成帳實不符。
>
> ⚠️ **收據可能延遲印出**：機台把收據送進列印佇列就視為成功，卡紙或缺紙時收據會等狀況排除後才吐出來（見正本「出金」）。因此「現場沒看到收據」**不等於**沒印，取消前務必先確認印表機狀態。

> ⚠️ **過渡期（機台暫無印表機，2026-09-03）**：出金由前台自行完成兩階段、以結算結果畫面代替收據（見正本「出金」小節）。此期間「收據是否已印出」改為確認前台是否已顯示結算結果畫面；出金停在「待確認」代表前台已請求出金但未完成回報，依人工出金連動取消處理。
>
> ⚠️ **現場若在機台的 Operator 選單執行過 Reset，機台就不會再回報這筆交易**——該待確認會永遠留著，必須由 Admin 手動取消清理。執行 Reset 後請一併通知後台。

### 相關業務規則（自正本摘錄）

| 項目 | 規則 |
| ---- | ---- |
| 交易核實 | **機台交易紀錄不提供核實操作**，本頁的核實狀態欄位**唯讀**（由「洗分出金核實」頁的操作回寫「核實狀態」「核實人員／時間」欄位）；核實一律於 帳務管理 \>「洗分出金核實」頁執行。核實的完整規則見正本與開發包⑤（`洗分出金核實_spec_v01.md`） |
| 重複回報 | 機台重複回報同一筆交易時，分數只異動一次，不會重複加減（入金與出金以交易編號辨識） |
| 單階段交易防重複（摘要） | ⚠️ 開分與洗分為單階段交易，請求**不帶唯一識別碼**，且機台**不會自動重送**（廠商回覆 2026-08-19）——平台把每一筆開分／洗分請求一律當作新交易處理，重複交易僅可能來自現場人員重新操作；機台顯示失敗時，現場一律**先查後台交易紀錄**再決定是否重做。全文（含開分／洗分的風險差異與廠商結案經過）屬開發包③，見正本「業務規則與驗證」同名條目 |
| 交易保留期限 | **入金**：尚未完成的交易超過 24 小時自動轉為「已逾時」。**出金：不設逾時**，待確認保留至完成、被新出金取代、人工出金連動取消或 Admin 手動取消為止 |
