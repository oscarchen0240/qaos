### 功能說明

「紅包」為優惠活動管理的新活動類型。帳號的**累計有效流水貢獻**每達到設定門檻，系統即產生一個紅包；玩家於前台開啟紅包，金額**直接入帳**至錢包（不經優惠彩金審核），並依設定掛上稽核。

線上站台與機台場館**同一套活動設定**，差異僅在前台領取方式與少數欄位（見「線上與機台的差異」）。

核心規則：

  - **循環發放：** 每累計滿一個門檻即產生一個紅包，超出部分續計入下一個；單一重置週期內可設發放上限
  - **等級規則：** 線上站台可依會員等級設定不同規則（累積門檻、單週期上限、獎勵、稽核倍數各自設定），未指定規則的等級統一套用「預設規則」，預設規則可關閉（其餘等級不參加）；規則即決定參加資格，不另設受眾範圍；每位會員同一時間只適用一個規則（見「規則設定」）
  - **累計基準：** 有效流水貢獻（有效投注額 × 遊戲貢獻系數，見 4.2 注單查詢）——貢獻系數為 0 的遊戲不計入累計，避免以低風險遊戲刷量
  - **幣種：** 活動可勾選多個「活動幣種」（可參加活動的錢包，同 6.5.2），各幣種注單的有效流水貢獻一律換算為站台**核心貨幣**後合併累計；門檻、紅包金額與預算皆以核心貨幣計，紅包一律派發核心貨幣（例：線上主站台核心貨幣為 USDT，玩家以 EUR 下注也計入累計、領到的紅包為 USDT）
  - **總預算：** 可選填活動總預算，發完即停止產生紅包；預算只能追加、不能調低
  - **金額：** 固定金額，或以權重表設定多個獎項金額與中獎機率隨機抽出；金額於**紅包產生當下即抽定**，開啟只是揭曉
  - **直接入帳：** 開啟即入錢包，寫入交易紀錄與稽核明細；不提供「線下給付」模式

### 線上與機台的差異

機台帳號為一台機台所有玩家共用（見實體機台正本「機台帳號」），紅包在機台場館**屬於機台、不屬於玩家**：累計是整台機台的流水，達標當下坐在台前的人開啟並取得。

| 項目 | 線上站台 | 機台場館 |
| ---- | ------- | ------- |
| 累計對象 | 會員帳號（＝一位玩家） | 機台帳號（多位玩家共用，跨玩家累計） |
| 參加對象 | 依規則設定：有等級規則的等級，及預設規則開啟時的其餘等級 | 該場館所有機台帳號（機台帳號不參與會員等級） |
| 規則設定 | 預設規則（可關閉）＋等級規則（可多組） | 僅預設規則且固定開啟，不顯示開關與「新增等級規則」 |
| 活動幣種 | 依鏈上錢包管理已開啟的幣種複選，換算為核心貨幣累計 | 固定 TWD（場館僅此一種），不顯示選項 |
| 派發幣種 | 站台核心貨幣（如 USDT），不可選 | 核心貨幣 TWD，不可選 |
| 重置時間點 | UTC+0 00:00 | 場館「日結時間」（與場館日結報表的營業日對齊） |
| 前台領取 | 右側紅包圖示達標時亮起，玩家點擊開啟紅包視窗領取（圖示與視窗線上、機台共用） | 同左，不自動彈出視窗 |
| 未開啟紅包作廢 | 週期重置或活動結束時 | 週期重置、活動結束，或該機台**完成洗分／出金**時 |
| 洗分／出金進行中 | — | 紅包**不能開啟**（含出金停在「待確認」期間），交易完成後依上一列作廢；交易取消、未成立或被取代則恢復可開啟。櫃檯人工出金視同出金（見業務規則「機台洗分／出金作廢」） |
| 稽核倍數 | 依活動設定 | 依活動設定；場館預設帶 0，填大於 0 時顯示警告（見下）；未完成的紅包稽核會扣減洗分／出金的核可金額 |
| 後台入口 | 優惠活動管理（全部活動類型） | 優惠活動管理僅開放「紅包」類型 |
| 報表 | 交易紀錄、稽核明細 | 同左，另於場館日結報表新增「紅包金額」欄 |

> ⚠️ **機台稽核警告**：機台帳號的稽核倍數預設 0 倍是刻意的（見開發包③「機台帳號的稽核」）——玩家隨時離台，稽核未完成會洗不出錢；且稽核掛在共用帳號上，前一位未完成的門檻會卡到下一位。機台場館的紅包稽核倍數填大於 0 時，表單顯示上述警告，站長確認後可儲存。紅包稽核未完成時，洗分與出金的核可金額**一律先扣除未完成稽核的部分**，不論出金設定的 TWD 稽核倍數是否為 0（見業務規則「機台稽核扣除」）。

> 📖 **機台「完成洗分／出金時作廢」不等於以場次判定優惠**：正本規定場次不得用於優惠（場次不等於玩家）。本規則的觸發條件是洗分／出金**交易**本身——玩家換分離台是最明確的離場訊號，紅包不該留給下一位；累計門檻則維持帳號層級、不因洗分／出金歸零。

### 新增優惠活動 — 紅包

**功能路徑：** 優惠活動管理 \> 新增優惠活動（麵包屑：優惠活動管理 / 新增優惠活動）

操作步驟：1. 選擇活動類型：紅包 2. 依序填寫以下欄位 3. 點擊底部「儲存」建立活動；點擊「取消」放棄並返回

**欄位說明：**

| 欄位 | 說明 |
| ---- | ---- |
| 活動類型 | 選擇「紅包」；機台場館僅此選項可選 |
| 活動條件 | 固定顯示「有效流水累計」，不可修改 |
| 活動幣種 | 勾選此活動適用的幣種（可複選，至少一個）；實際顯示的項目依鏈上錢包管理中已開啟的幣種為準，預設勾選核心貨幣。與 6.5.2 充值活動的「活動幣種」意義相同——即可參加活動的錢包；以勾選幣種下注的注單計入累計（非核心貨幣依系統匯率換算，見業務規則）；**機台場館不顯示**（固定 TWD）；建立後不可修改 |
| 派發幣種 | 唯讀，自動顯示站台核心貨幣（主站台層級設定，見站台列表「核心貨幣」）；門檻、紅包金額、總預算皆以此幣種計 |
| 活動時間 | 永久（無期限持續生效）或區間（以日曆選擇起訖日期與時間，UTC+0） |
| 重置方式 | 累計歸零週期：每日 / 每週一 / 每月 1 日 / 不重置。線上站台於 UTC+0 00:00 切分；**機台場館於場館「日結時間」切分**（表單提示同時顯示該場館日結時間的 UTC+0 與台灣時間，例：「每日／每週一／每月 1 日於本場館日結時間歸零（目前設定：UTC+0 20:00，台灣時間 04:00）」）；建立後不可修改 |
| 活動總預算 | 選填，空白表示不限；單位為核心貨幣，最多 1 位小數。**所有規則共用一池**。預算占用＝已入帳＋待開啟紅包金額，用罄即停止產生紅包（見業務規則）。建立後**只能追加調高**（見「追加預算」） |
| 規則設定 | 累積門檻、單週期發放上限、獎勵方式、稽核倍數依規則分別設定，見下方「規則設定」；建立後不可修改 |
| 前台圖示選擇 | 從下拉選單選取前台紅包顯示的圖示 |
| 預設語系 | 設定活動名稱與說明欄的預設語系；當前台無法匹配用戶語系時，以此語系顯示 |

**規則設定**

規則同時決定「誰能參加」與「參加者適用的門檻與獎勵」，不另設受眾範圍。每位會員依當下會員等級只適用一個規則，前台也只顯示一組進度。

**等級來源：** 適用等級的選項讀取 6.2 會員等級設定中**生效的會員等級方案**，顯示為「VIP 等級序號・等級名稱」（例：「3・Silver」）。等級規則以 **VIP 等級序號**記錄，不綁定特定會員等級方案；切換生效方案時依序號對應（見業務規則「切換會員等級方案」）。

會員等級的判定順序：該等級序號有等級規則 → 適用該等級規則；否則預設規則開啟 → 適用預設規則；兩者皆無 → 不參加。

| 規則 | 說明 |
| ---- | ---- |
| 預設規則 | 以開關設定「其餘等級參加」，預設開啟。**開啟**：套用所有**未被等級規則勾選**的等級序號，含日後切換會員等級方案後才出現的序號；規則欄位必填。**關閉**：其餘等級不參加，規則欄位隱藏、不需填寫。機台場館固定開啟、不顯示開關 |
| 等級規則 | 選填。點擊「+ 新增等級規則」增加，每組右上角可移除；每組勾選適用等級（可複選，至少一個）；**一個等級序號只能屬於一個規則**，已被其他規則勾選的等級停用並標示所屬規則。**機台場館不顯示** |

  - 規則依序命名「預設規則」「等級規則 1」「等級規則 2」…，用於後台列表與紅包明細
  - 預設規則開啟時，其標題旁顯示實際套用的等級（例：「套用：1・Starter、2・Bronze、5・Platinum，及其他未勾選的等級序號」）
  - 常見設定：全站同一套規則 → 只用預設規則；僅部分等級參加 → 關閉預設規則、以等級規則勾選參加的等級

每個規則各自設定以下欄位：

| 欄位 | 說明 |
| ---- | ---- |
| 適用等級 | 僅等級規則；勾選此規則適用的會員等級，選項為生效會員等級方案的所有等級（「序號・等級名稱」） |
| 累積門檻 | 每累計滿此有效流水貢獻即產生一個紅包（循環計算，單位為核心貨幣）；最多 1 位小數 |
| 單週期發放上限 | 單一帳號在一個重置週期內最多產生的紅包數；達上限後停止累計，直到下次重置 |
| 獎勵方式 | 固定金額 / 隨機金額（權重表） |
| 稽核倍數 | 紅包金額的提領稽核倍數；入帳時增加所需有效投注額 ＝ 紅包金額 × 倍數；可填 0、最多 1 位小數、不設上限；機台場館預設 0，大於 0 時顯示稽核警告 |

活動名稱／說明欄、活動幣種、重置方式、活動時間、活動總預算、前台圖示、預設語系為整個活動共用，不分規則。

**獎勵方式**

| 獎勵方式 | 設定欄位 | 說明 |
| ------- | ------- | ---- |
| 固定金額 | 紅包金額 | 每個紅包金額固定；須大於 0，最多 1 位小數 |
| 隨機金額 | 權重表 | 設定各獎項金額與中獎機率，紅包產生時依機率抽出其中一項 |

**權重表**（獎勵方式選「隨機金額」時顯示，每列一個獎項）

| 欄位 | 說明 |
| ---- | ---- |
| 紅包金額 | 該獎項金額（核心貨幣），須大於 0；最多 1 位小數 |
| 中獎機率 | 該獎項被抽中的百分比；最多 1 位小數 |

  - 可點擊「+ 新增」增加獎項，每列右側可移除；至少保留一列
  - 所有列的中獎機率合計須為 100%，否則阻擋儲存

**成本試算**（系統自動計算，不可編輯，僅供預算評估；**每個規則各自計算**，顯示於該規則區塊內）

| 項目 | 計算方式 |
| ---- | ------- |
| 單個紅包期望金額 | Σ（各獎項金額 × 中獎機率）；固定金額時即紅包金額 |
| 每帳號單週期最高成本 | 權重表最大獎項金額（或固定金額）× 單週期發放上限 |
| 成本占比 | 單個紅包期望金額 ÷ 累積門檻；代表平台每收 100 有效流水貢獻回饋多少 |
| 預算約可發放 | 活動總預算 ÷ 該規則單個紅包期望金額（無條件捨去），即假設預算全由該規則發放；未設總預算時顯示「不限」 |

  - 顯示格式（成本試算與整體試算皆同）：金額取 2 位小數並去除尾端的 0（例：19.00 顯示 19、19.50 顯示 19.5）；成本占比以百分比顯示、取 2 位小數（例：1.90%）

**整體試算**（有兩組以上生效的規則時，顯示於規則設定區塊下方；新增／移除等級規則、改勾適用等級、切換預設規則開關或修改任一規則欄位時即時重算）

各規則以其**涵蓋會員人數**加權：涵蓋會員人數＝該規則適用等級在 6.2 生效會員等級方案的「會員人數」合計（預設規則為所有未被等級規則勾選的等級合計；關閉的預設規則不計入）。各規則區塊標題旁同時顯示涵蓋會員人數。

| 項目 | 計算方式 |
| ---- | ------- |
| 整體期望金額 | Σ（各規則單個紅包期望金額 × 涵蓋會員人數）÷ Σ 涵蓋會員人數 |
| 每帳號單週期最高成本 | 各規則「每帳號單週期最高成本」取最大值 |
| 整體成本占比 | Σ（各規則成本占比 × 涵蓋會員人數）÷ Σ 涵蓋會員人數 |
| 預算約可發放 | 活動總預算 ÷ 整體期望金額（無條件捨去）；未設總預算時顯示「不限」 |

  - 涵蓋會員人數合計為 0 時，整體期望金額、整體成本占比與預算約可發放顯示「—」
  - 加權假設每位會員產生紅包的機會相同；實際上高等級會員流水通常較高、產生較多紅包，整體數值可能偏低。畫面標註「依目前會員人數估算，僅供參考」

**活動名稱／說明欄**

可依語系分別設定；先選擇語系，再填入對應內容。

| 欄位 | 說明 |
| ---- | ---- |
| 語系 | 選擇欲設定的語系 |
| 活動名稱 | 最多 25 字元；於前台紅包視窗顯示 |
| 說明欄 | 該語系的活動說明文字 |

### 紅包狀態

| 狀態 | 色標 | 觸發 | 說明 |
| ---- | ---- | ---- | ---- |
| 待開啟 | 黃色 | 累計達門檻時系統產生 | 金額已抽定並占用預算，前台可開啟（機台洗分／出金進行中暫時不能開啟） |
| 已入帳 | 綠色 | 玩家於前台開啟 | 金額已入錢包、稽核已掛上、已寫入交易紀錄 |
| 已作廢 | 灰色 | 系統自動 | 週期重置、活動結束（到期或取消排程）時作廢；機台另於完成洗分／出金時作廢，洗分／出金完成後才達標者直接以本狀態建立（見業務規則「洗分／出金後才達標」）。不可復原、不補發；作廢釋放所占用的預算 |

### 前台呈現說明

**紅包圖示（線上站台與機台場館共用）**

活動進行中，前台畫面右側常駐顯示該活動「前台圖示選擇」所選的紅包圖示，點擊開啟紅包視窗：

| 圖示狀態 | 條件 | 說明 |
| ------- | ---- | ---- |
| 暗 | 無待開啟紅包 | 可點擊查看活動與累計進度 |
| 亮 | 有待開啟紅包 | 達標產生紅包時**亮起提示，不自動彈出視窗**；玩家自行點擊開啟 |

  - 活動結束（到期或取消排程）後**立即從前台移除**圖示（未開啟的紅包已於結束時作廢）
  - 線上另沿用其他優惠活動有可領取項目時的提示：右上角禮物圖示亮紅點

**紅包視窗（線上站台與機台場館共用）**

線上與機台使用**同一個紅包活動視窗**，顯示以下資料；不顯示規則名稱。機台場館的差異見下方「機台場館」。

| 資料 | 說明 |
| ---- | ---- |
| 活動名稱 | 依語系顯示 |
| 紅包金額 | **無待開啟紅包時**：一律加「最高」——固定金額顯示「最高 ＄該金額」；隨機金額（權重表）顯示「最高 ＄最大獎項金額」（例：權重表 8／18／88 顯示「最高 88」）。**有待開啟紅包時**：顯示下一個待開啟紅包的實際金額（固定金額即該金額；隨機金額為達標產生時已抽定的金額，見業務規則「金額抽定時點」），不加「最高」；確認領取視窗同樣顯示實際金額。稽核倍數大於 0 時另顯示「稽核倍數 xN」，為 0 時不顯示 |
| 累計進度 | **有待開啟紅包時**顯示滿格（適用規則的累積門檻 ／ 累積門檻）並標示「已達有效流水門檻」；**全部領完後**改顯示距下一個紅包的進度：目前累計 ／ 適用規則的累積門檻，並顯示尚差多少。目前累計＝本週期累計扣除已產生紅包所用掉的門檻（例：門檻 1,000、本週期累計 1,084、已產生 1 個且已領取 → 顯示 84 ／ 1,000，尚差 916）。此為前台顯示規則，後台實際累計不因待開啟而暫停；後台紅包明細的「週期累計」仍為本週期累計總額（1,084） |
| 活動時間 | 距活動結束的**倒數**，格式一律 `HH:MM:SS`（超過 24 小時以小時累加，例：「53:12:30」）；永久活動顯示「永久」 |
| 重置時間 | 下次重置的時間點（線上 UTC+0 00:00；機台為場館日結時間）；重置方式為「不重置」時顯示「不重置」。重置時間的時區呈現方式沿用前台既有優惠活動的時間顯示 |
| 總獎池 | 活動總預算；未設總預算顯示「不限」；預算用罄（見業務規則「預算用罄」）時顯示「獎池已發完」 |
| 本期已獲得 | 本週期已產生數 ／ 適用規則的單週期發放上限；已產生數含待開啟、已入帳與已作廢（用詞為「已獲得」而非「已領取」，避免玩家誤以為未開啟的不計入） |
| 活動說明 | 取自後台「說明欄」（依語系） |
| 領取按鈕 | 顯示待開啟數量（例：「領取獎勵（2）」），**每次領取一個**；無待開啟紅包時按鈕停用 |

**領取流程**

  1. 點擊亮起的紅包圖示，開啟紅包視窗（顯示下一個待開啟紅包的金額）
  2. 點擊「領取獎勵（N）」，跳出**確認領取視窗**「確認領取獎勵」：顯示活動名稱、紅包金額、稽核倍數（為 0 時不顯示），以及「確定要領取此獎勵嗎？」；［取消］關閉確認視窗、不領取；［確認領取］送出
  3. 送出後按鈕顯示「處理中…」，完成即入帳（線上入錢包、機台分數增加）；仍有待開啟紅包時，紅包視窗改顯示下一個紅包的金額，可再次領取

  - 累計因注單取消／重結算暫時為負時，進度顯示 0；本週期已達發放上限時顯示「本期已達上限」
  - 有待開啟紅包時，於**重置前 1 小時**起提示「未開啟的紅包將於重置時作廢」；重置方式為「不重置」的活動，於活動結束前 1 小時起提示

**線上站台**

  - 會員等級變動後，進度、上限與紅包金額即改以新規則顯示（見業務規則「會員等級變動」）
  - 會員當下等級沒有適用規則（不參加）時，前台**不顯示**此活動；但該會員仍有待開啟紅包時照常顯示供領取，累計進度處顯示「目前等級不參加」（見業務規則「等級無適用規則」）

**機台場館**

  - 紅包圖示與視窗同上，資料以機台帳號計（累計為整台機台跨玩家）；重置時間為場館日結時間
  - 累計達門檻時，紅包圖示亮起，**不自動彈出視窗**；玩家點擊圖示依上述流程領取，分數即時增加
  - 玩家於錢包彈窗按結算鍵、或店員以鑰匙選單洗分時，若尚有待開啟紅包，機台畫面先跳出**可取消的確認視窗**「尚有紅包未開啟，交易完成後將作廢」：［返回開啟紅包］關閉視窗、不送出交易；［繼續結算］送出交易。店員洗分時同一視窗由店員確認
  - 洗分或出金請求送出後、交易完成前（含出金停在「待確認」期間），領取按鈕停用並顯示「交易處理中」；交易取消、未成立或被取代即恢復可領取

> 📌 前台動畫與版面細節由前台設計另定，本 spec 僅定義觸發時點、資料與用詞。

### 活動排程

於 6.5.1 活動排程新增「紅包活動」子分頁，欄位沿用既有排程列表（活動名稱、排程說明、取消排程），另加「狀態」欄。取消排程後活動停止累計與產生紅包，已產生未開啟的紅包一併作廢。

**活動狀態**（依活動時間即時判定）

| 狀態 | 判定 | 可用操作 |
| ---- | ---- | ------- |
| 排程中 | 尚未到開始時間 | 取消排程、追加預算 |
| 進行中 | 開始時間 ≦ 現在 ＜ 結束時間（永久活動開始後一律為進行中） | 取消排程、追加預算 |
| 已結束 | 已過結束時間 | 僅可點擊活動名稱檢視紅包明細 |
| 已取消 | 已取消排程 | 僅可點擊活動名稱檢視紅包明細 |

  - 已結束與已取消的活動**仍列於列表**，供查閱紅包明細；「取消排程」「追加預算」僅於排程中、進行中顯示
  - 預算用罄不是獨立狀態，於狀態旁另加標示（見下）

機台場館的活動排程僅顯示「紅包活動」子分頁。

列表於排程說明外，另顯示活動幣種、累積門檻／單週期上限、獎勵方式、稽核倍數與**預算使用**（已占用 ／ 總預算，未設預算顯示「不限」）。預算用罄的活動於狀態旁標示「預算用罄」。

活動名稱下方顯示**參加等級**摘要：預設規則開啟時為「全部等級」，關閉時列出各等級規則勾選的等級（例：「3・Silver、4・Gold」）；機台場館不顯示。累積門檻／單週期上限、獎勵方式、稽核倍數顯示**預設規則**的值（預設規則關閉時顯示等級規則 1）；有等級規則時另標示「＋N 個等級規則」，完整內容見紅包明細。

**追加預算**

設有總預算、且狀態為進行中或排程中的活動，列表提供「追加預算」操作：

  1. 點擊「追加預算」開啟視窗，顯示目前總預算、已占用與剩餘
  2. 輸入新的總預算（須大於目前總預算，最多 1 位小數）；輸入值小於或等於目前總預算時，「確認」鈕停用，欄位下方提示「新的總預算須大於目前總預算」
  3. 點擊「確認」，新預算即時生效；原本預算用罄的活動恢復產生紅包

  - 只能調高、不能調低；未設總預算（不限）的活動不提供此操作
  - 後端同樣檢查，新預算不大於目前總預算時拒絕、資料不變
  - 每次追加寫入 **7.4 操作紀錄**（操作人員、時間、活動名稱、調整前與調整後金額）；紅包明細不另顯示追加歷程。7.4 操作紀錄為實體機台正本規劃新增的頁面（手冊 v01 尚未定義），可檢視角色隨該頁定義

### 計算範例

> 以下匯率與金額皆為示意，實際匯率依系統匯率（幣安 API，見業務規則「匯率來源」）。

**線上站台（核心貨幣 USDT）**

活動設定：活動幣種 USDT、EUR、USD（未勾選 BTC）；累積門檻 1,000 USDT；每日重置；單週期發放上限 5 個；權重表 8 USDT（60%）／18 USDT（30%）／88 USDT（10%）；稽核倍數 1 倍；總預算 5,000 USDT。

玩家 A 當日注單：

| # | 下注幣種 | 有效投注 | 貢獻系數 | 有效流水貢獻 | 結算當下匯率 | 換算為 USDT | 週期累計 |
| - | ------- | ------- | ------- | ---------- | ---------- | ---------- | ------- |
| 1 | USDT | 400 | 100% | 400 USDT | — | 400 | 400 |
| 2 | EUR | 300 | 100% | 300 EUR | 1 EUR = 1.08 USDT | 324 | 724 |
| 3 | USD | 500 | 50%（真人遊戲） | 250 USD | 1 USD = 1.00 USDT | 250 | 974 |
| 4 | BTC | 0.01 | 100% | — | — | 不計（BTC 不在活動幣種內） | 974 |
| 5 | EUR | 100 | 100% | 100 EUR | 1 EUR = 1.10 USDT | 110 | **1,084** |

  - **第 5 筆結算時**累計達 1,000，產生 1 個紅包並當下抽定金額（例：18 USDT）；超出的 84 續計入下一個門檻。預算占用 0 → 18，剩餘 4,982
  - **不重算**：第 2 筆以結算當下的 1.08 換算為 324；之後 EUR 匯率變動，第 2 筆仍為 324
  - **玩家 A 開啟紅包**：18 USDT 入 USDT 錢包（即使玩家 A 多以 EUR 下注，派發仍為核心貨幣）；交易紀錄新增「紅包 +18 USDT」；所需有效投注額增加 18 USDT（18 × 1 倍），稽核明細類型「紅包」
  - **紅包明細**：該筆週期累計顯示 1,084 USDT、紅包金額 18 USDT
  - **前台**：紅包圖示亮起；未領取前視窗顯示紅包金額 18 USDT、累計進度滿格「已達有效流水門檻」、本期已獲得 1 ／ 5、總獎池 5,000 USDT；領取後圖示轉暗，紅包金額改顯示「最高 88」（固定金額時亦加「最高」），累計進度顯示 84 ／ 1,000（尚差 916）

**線上站台：等級規則與會員升級**

活動設定：每日重置。預設規則（開啟）：累積門檻 1,000 USDT、單週期上限 5 個、固定 10 USDT、稽核 1 倍。等級規則 1（3・Silver、4・Gold）：累積門檻 800 USDT、單週期上限 8 個、固定 30 USDT、稽核 1 倍。

玩家 B 為 2・Bronze（適用預設規則），當日：

| 時點 | 事件 | 週期累計 | 本週期已產生 | 說明 |
| ---- | ---- | ------- | ---------- | ---- |
| 1 | 注單結算，累計至 1,200 | 1,200 | 1 | 達預設規則門檻 1,000，產生 10 USDT 紅包（待開啟）；超出 200 續計 |
| 2 | 會員等級升為 3・Silver | 1,200 | 1 | 改用等級規則 1；累計進度（距下一個紅包已累計 200）與已產生數保留；本時點不觸發產生 |
| 3 | 注單結算，累計 +700 | 1,900 | 2 | 以新門檻 800 判斷：200＋700 ≥ 800，產生 30 USDT 紅包；超出 100 續計 |
| 4 | 開啟兩個紅包 | — | — | 時點 1 的紅包入帳 10 USDT、時點 3 的入帳 30 USDT；金額與稽核倍數維持各自產生當下的規則 |

  - 單週期上限改以等級規則 1 的 8 個計，本週期已產生數（含升級前的 1 個）一併計入
  - 若玩家 B 升級前本週期已產生 8 個以上，升級後即達新規則上限，停止累計直到重置
  - **紅包明細**：時點 1 的紅包「適用規則」顯示「預設規則（2・Bronze）」，時點 3 的顯示「等級規則 1（3・Silver）」

**機台場館（核心貨幣 TWD）**

  - 場館僅 TWD，不顯示活動幣種、不涉及換算
  - 重置週期與場館日結報表的營業日對齊。例：場館日結時間設定為 UTC+0 20:00（台灣時間 04:00）時，每日重置的週期為台灣時間今日 04:00 至次日 04:00——玩家凌晨 2 點的流水仍計入前一營業日；每週自週一的營業日起算、每月自 1 日的營業日起算（04:00 僅為範例，實際依各場館設定的日結時間）
  - 活動期間修改日結時間（見業務規則「日結時間變更」）。例：每日重置、原日結時間為台灣時間 04:00：

| 修改時點（台灣時間） | 改為 | 本週期如何結束 |
| ---- | ---- | ---- |
| 10:00 | 02:00（調早） | 本週期起於今日 04:00，之後尚未經過 02:00 → 延至次日 02:00 結束（約 22 小時） |
| 03:00 | 02:00（調早） | 本週期起於前一日 04:00，今日 02:00 已經過 → 視同到達重置點，**立即重置** |
| 10:00 | 06:00（調晚） | 延至次日 06:00 結束（約 26 小時） |
| 05:00 | 06:00（調晚） | 今日 04:00 已重置過，**不倒退**重來；本週期延至次日 06:00 結束 |

  - 店員送出洗分後、洗分完成前，機台畫面的紅包按鈕停用並顯示「交易處理中」；洗分完成時未開啟的紅包作廢（累計不歸零），洗分取消或未成立則恢復可開啟

### 業務規則與驗證

| 項目 | 規則 |
| ---- | ---- |
| 累計基準 | 有效流水貢獻（有效投注額 × 貢獻系數），以注單結算時點計入；只計以「活動幣種」下注的注單 |
| 注單取消／重結算 | 遊戲商取消或重結算注單送來的負值有效流水貢獻**照實扣減**，累計可暫時為負（之後須先補回）；只扣在**原注單所屬的週期**，原週期已重置或活動已結束時不扣。已產生的紅包（待開啟、已入帳）不受影響、不追回；前台進度最低顯示 0。例：累計 84，一筆 300 的注單重結算（－300＋300）後仍為 84 |
| 幣種換算 | 非核心貨幣注單的有效流水貢獻，於注單**結算當下**依系統匯率換算為核心貨幣，**四捨五入至小數 2 位**後計入累計；顯示與達標判斷皆用此值；換算後不因匯率變動重算 |
| 匯率來源 | 系統匯率直接取用**幣安（Binance）API** 的結果（系統已完成串接）；取價方式與更新頻率依既有串接，由工程定義 |
| 取價失敗 | 結算當下取不到該幣種匯率（斷線、限流、無對應交易對等）時，沿用該幣種**最近一次成功取得**的匯率換算；該幣種從未成功取得匯率時，該筆注單不計入累計、不補計，並記錄異常供工程追查 |
| 重置時間點 | 線上站台 UTC+0 00:00；機台場館為場館「日結時間」，週期與場館日結報表的**營業日**對齊：每日＝一個營業日，每週自週一的營業日起算，每月自 1 日的營業日起算 |
| 日結時間變更 | 活動期間場館修改日結時間時**立即生效**（與場次日結、場館日結報表同步）；週期只往前、不倒退：**調早**時，本週期起點之後已經過新的重置時點者，視同到達重置點、立即重置，尚未經過者延至該重置時點結束；**調晚**時，本週期一律延至原結束點之後的第一個新重置時點結束（不立即重置、不產生短週期）。已重置過的週期不重來 |
| 規則適用 | 會員依**當下**會員等級適用規則：該等級有指定等級規則時用之，否則用預設規則；機台帳號一律適用預設規則 |
| 會員等級變動 | 活動期間會員升降級時**立即改用新等級的規則**：本週期累計進度與已產生數保留；變動當下不觸發產生，下一筆計入的注單結算時改以新規則的累積門檻判斷（累計已達多個門檻時循環產生）；單週期上限以本週期已產生數（含變動前）對照新規則上限，已達上限即停止累計直到重置；已產生的紅包（含待開啟）金額與稽核倍數維持產生當下的規則，不受影響 |
| 等級無適用規則 | 預設規則關閉、會員變動至沒有等級規則的等級時停止累計；本週期累計進度保留、待開啟紅包仍可開啟；同一週期內變動回有規則的等級時依該規則續計 |
| 切換會員等級方案 | 活動期間於 6.2 切換生效的會員等級方案時，等級規則**依 VIP 等級序號對應**新方案的等級（例：勾選序號 3 者，改適用新方案的第 3 級）。新方案沒有的序號：該勾選不對應任何會員。新方案多出、未被勾選的序號：依預設規則開關，開啟時適用預設規則、關閉時不參加。會員因切換而序號改變時，視同「會員等級變動」處理。活動設定與列表的等級名稱改顯示新方案的名稱；新方案沒有的序號顯示「序號（目前方案無此等級）」 |
| 循環計算 | 每累計滿門檻產生一個紅包，超出部分續計入下一個 |
| 達上限 | 單週期產生數達上限後停止累計，直到下次重置；產生達上限的那一個紅包時，超出門檻的**餘數保留**（例：門檻 1,000、上限 5 個，第 5 個產生時累計為 1,084，保留 84），之後結算的注單不再計入；會員等級變動使上限調高時，自保留的餘數續計 |
| 金額抽定時點 | 紅包產生當下抽定金額並記錄，開啟時不重抽 |
| 預算占用 | 設有總預算時，預算占用＝已入帳＋待開啟紅包金額；紅包作廢即釋放占用 |
| 預算用罄 | 紅包產生當下抽出的金額大於剩餘預算時，不產生該紅包，活動標示「預算用罄」並停止產生紅包；用罄期間帳號累計照常推進，達標的門檻**不產生、不補發**。追加預算或占用被釋放後恢復產生 |
| 追加預算 | 總預算建立後只能調高；未設總預算的活動不可改為有預算 |
| 直接入帳 | 開啟即入錢包，不經 3.3 優惠彩金審核 |
| 稽核 | 入帳時所需有效投注額增加 紅包金額 × 稽核倍數，寫入 4.4 稽核明細（類型「紅包」） |
| 交易紀錄 | 入帳時寫入 4.1 交易紀錄查詢，交易類型「紅包」，正值 |
| 重置作廢 | 週期重置時該帳號所有待開啟紅包作廢；已入帳紀錄不受影響 |
| 機台洗分／出金作廢 | 機台帳號完成洗分或出金（扣分成功）當下，該帳號待開啟紅包作廢；累計進度**不歸零**。櫃檯對機台帳號**人工出金**視同出金完成，作廢原因「機台出金」；人工入金不影響紅包。過渡期由前台完成的出金同樣適用 |
| 洗分／出金後才達標 | 注單非同步計入，上一位玩家的最後幾局可能在洗分／出金完成後才計入並達標。觸發達標的注單所屬場次**已因洗分或出金結束**時，紅包直接以「已作廢」建立（作廢原因：機台洗分／機台出金）：照常抽定金額並計入本週期已產生數，不占用預算、紅包圖示不亮起；累計照常、不歸零。場次因逾時、日結結算或歸零結束者不適用，照常產生待開啟紅包 |
| 機台交易進行中 | 紅包入帳與機台洗分／出金使用同一把帳號鎖：洗分或出金請求送出後、交易完成前，紅包不可開啟；出金停在「待確認」（不設逾時）期間同樣不可開啟。交易完成依上列作廢；交易取消、未成立、被新出金取代或由管理員手動取消時，原交易視為未成立、紅包恢復可開啟（新出金送出後再次鎖定） |
| 機台入帳場次 | 紅包入帳歸屬**入帳當下**進行中的場次（不是紅包產生當下的場次）；場館日結報表「依場次明細」該場次的紅包金額、期末餘額與餘額驗算皆含此筆 |
| 開啟時無場次 | 機台開啟紅包時若無進行中的場次（例：場次已逾時結束，或分數歸零結束後才開啟），紅包入帳即建立新場次（期初餘額＝當下機台分數），紅包入帳歸屬該場次 |
| 機台稽核扣除 | 機台帳號有未完成的稽核（含紅包稽核）時，洗分與出金的核可金額須先扣除未完成稽核的部分；扣除條件為「帳號有未完成稽核」，**不再以出金設定的 TWD 稽核倍數大於 0 為前提**（出金設定 0 倍、紅包稽核倍數大於 0 時同樣扣除） |
| 機台額度上限 | 紅包入帳不受場館額度上限阻擋（不因額度拒絕已達標的獎勵），但入帳後計入全場館餘額合計，影響後續開分／入金的額度檢核 |
| 同時進行的活動 | 同一站台同一時間僅能有一個進行中的紅包活動（排程時間重疊時阻擋儲存）。各站台獨立判斷——主站台與子站台各自計算、可各自辦一個；活動只涵蓋建立活動之站台的會員，**不涵蓋子站台**。重疊判斷只計「進行中」與「排程中」的活動；**已取消**的活動不占用時段，取消後可立即以相同時段重建 |
| 排除規則 | 機台帳號參與紅包為開發包⑥排除規則「6.5 優惠活動」的**逐項解除**（僅解除紅包類型，其餘優惠類型維持排除），須經政策層處理，不得在紅包功能內硬編碼帳號類型判斷 |
| 機台啟用方式 | 隨版本對所有機台場館**一次上線**，不設場館開關；上線後場館是否參加由站長自行決定（建立紅包活動即參加）。上線前機台場館的選單與機台帳號維持完全排除 |
| 規則驗證 | 預設規則關閉時至少須有一個等級規則；每個等級規則至少勾選一個等級；一個等級只能屬於一個規則。以下門檻、上限、權重表規則逐規則檢查（關閉的預設規則不檢查） |
| 門檻與上限 | 累積門檻須大於 0；單週期發放上限須為大於 0 的整數；總預算有填時須大於 0 |
| 數值精度 | 累積門檻、紅包金額、中獎機率、總預算、稽核倍數最多 1 位小數；稽核倍數可為 0、不設上限 |
| 活動幣種 | 至少勾選一個 |
| 權重表 | 機率合計須為 100%；各列金額須大於 0；至少一列 |
| 不可修改 | 活動幣種、重置方式、規則設定（含預設規則開關、各規則適用等級、累積門檻、單週期上限、獎勵設定、稽核倍數）於建立後不可修改；需調整時取消排程後重建。唯一例外為總預算可追加調高 |
| 活動名稱字數 | 最多 25 字元 |
| 驗證回應 | 以上驗證不通過時，前端於該欄位標紅框並於下方提示，點擊「儲存」時整體再檢查一次並捲動至第一個錯誤欄位；後端同樣驗證，不通過即拒絕、資料不寫入（錯誤代碼由後端定義）。提示文字：「請至少勾選一個活動幣種」「請至少新增一個等級規則」「請至少勾選一個適用等級」「此等級已屬於其他規則」「累積門檻須大於 0」「單週期發放上限須為大於 0 的整數」「總預算須大於 0」「紅包金額須大於 0」「機率合計須為 100%」「最多 1 位小數」「活動名稱最多 25 字元」 |
