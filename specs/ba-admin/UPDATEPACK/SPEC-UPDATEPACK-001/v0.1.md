### 一、多幣別錢包展開顯示

**功能路徑：** 會員與加盟商 \> 會員列表（列表、側邊簡易資料面板、會員詳細資料頁）

#### 功能說明

站台可同時開啟多個幣別的錢包。會員的餘額類欄位預設為**收合**狀態，只顯示該站台**核心貨幣**錢包的金額；當站台開啟一種以上幣別時，欄位右側顯示展開箭頭，點擊後逐列列出各幣別錢包的金額，再次點擊收合。

#### 適用欄位

| 位置 | 欄位 |
| ---- | ---- |
| 2.1.3 會員列表 | 帳戶餘額（主錢包） |
| 2.1.4 側邊簡易資料面板〈帳戶資訊〉 | 帳戶餘額（主錢包）、提領所需有效投注額（流水錢包）、可提領餘額 |
| 2.1.5 會員詳細資料頁〈帳務資訊〉 | 帳戶餘額（主錢包）、提領所需有效投注額（流水錢包）、可提領餘額 |

#### 顯示規則

| 規則 | 說明 |
| ---- | ---- |
| 幣別清單來源 | 依「帳務管理 \> 鏈上錢包管理」中狀態為**啟用**的幣種為準（含法幣頁籤的幣別）；狀態為關閉或禁用的幣種不列出。幣種增減隨鏈上錢包管理的啟用狀態連動，本功能不另行設定幣別清單 |
| 展開箭頭顯示條件 | 已啟用幣種**超過一種**時才顯示展開箭頭；僅啟用一種幣別的站台不顯示箭頭，維持單行呈現 |
| 收合時顯示的數值 | 該站台**核心貨幣**錢包的餘額——**不做匯率換算，也不是各幣別的加總**。核心貨幣為主站台層級的設定，底下子站台一律繼承、不可各自指定 |
| 展開後的排列順序 | 核心貨幣固定列於第一列，其餘已啟用幣種依鏈上錢包管理的幣種順序接續排列；每列顯示「幣種代碼 ＋ 金額」 |
| 金額為 0 的幣別 | 仍列出並顯示 0.00，不因無餘額而隱藏 |
| 展開狀態的保留 | 逐欄各自獨立展開／收合，僅作用於當次瀏覽；換頁、重新查詢或重新進入頁面後回到收合預設 |

> ⚠️ **不變更的範圍**：2.1.2 篩選器的「帳戶餘額（主錢包）min ～ max」與列表底部「總計」列維持現行行為——皆以收合時的單一數值（核心貨幣錢包餘額）為準，不依幣別拆分，也不提供幣別選擇。

#### 機台場館的情形

機台場館的核心貨幣為 **TWD**，鏈上錢包管理在機台場館僅顯示法幣 TWD 一個頁籤、只啟用這一種幣別，因此**機台帳號的餘額欄不顯示展開箭頭、維持單行呈現**；收合值即該帳號的主錢包（TWD）餘額，也就是機台上顯示的**分數**。

> ⚠️ **實作不得把「單一幣別」寫死**——幣別數量須由鏈上錢包管理的啟用狀態決定，未來場館啟用第二種幣別時展開行為要能自動適用。

### 二、存款／提款累計欄位

**功能路徑：** 會員與加盟商 \> 會員列表（2.1.2 篩選器、2.1.3 列表欄位）

#### 功能說明

會員列表的存款次數／存款金額／提款次數／提款金額四個欄位，**僅計系統入金與系統出金，一律不含人工入金與人工出金**。機台的四種金流依「是否需要核實」分成兩種計入時點。

#### 機台四種金流的計入規則

| 金流 | 計入欄位 | 計入時點 |
| ---- | ------- | ------- |
| 機台**開分** | 存款次數／存款金額 | **交易完成當下直接累計**，不需核實 |
| 機台**入金** | 存款次數／存款金額 | **交易完成當下直接累計**，不需核實 |
| 機台**洗分** | 提款次數／提款金額 | 於「洗分出金核實」頁**核實當下**累計；待核實不計、**已作廢永不計** |
| 機台**出金** | 提款次數／提款金額 | 於「洗分出金核實」頁**核實當下**累計；待核實不計、**已作廢永不計** |

#### 欄位定義

| 欄位 | 說明 |
| ---- | ---- |
| 存款次數 | 會員累計成功入金的次數，僅計系統入金，**不含人工入金**；機台開分與機台入金於交易完成當下累計 |
| 存款金額 | 會員累計成功入金的總金額，計算範圍同上；金額以站台**核心貨幣原值**累計，**不換算 USDT** |
| 提款次數 | 會員累計成功出金的次數，僅計系統出金，**不含人工出金**；線上出金於出金審核按「通過」當下累計，機台洗分與機台出金於核實當下累計 |
| 提款金額 | 會員累計成功出金的總金額，計算範圍同上；金額以站台**核心貨幣原值**累計，**不換算 USDT** |

篩選器的四個範圍欄位（存款次數／存款金額／提款次數／提款金額）與列表欄位採**同一套定義**。

> ⚠️ 手冊原文曾寫「**含**人工入金／出金」，該敘述已作廢——人工存入與人工提出**一律不計入**這四個欄位。

相依：機台四種金流的產生與狀態流轉屬開發包③；核實與作廢的操作屬開發包⑤（`洗分出金核實_spec_v01.md`）。

### 三、機台憑證（JWT）

**功能路徑：** 會員與加盟商 \> 會員列表 \> 會員詳細資料頁〈機台憑證〉區塊（機台帳號才顯示）

#### 功能說明

機台憑證供機台主控程式與平台 API 通訊，與機台帳號的登入帳密各自獨立、互不影響。憑證格式為 **JWT（JSON Web Token）**，由平台簽發；機台每次呼叫平台 API 時以 `Authorization: Bearer <token>` 附帶。

#### 區塊欄位

| 欄位 | 說明 |
| ---- | ---- |
| 憑證狀態 | 未產生／已產生 |
| 憑證（遮罩） | 已產生時以**前後各 4 碼**遮罩顯示，中間以 · 遮蔽；未產生顯示「—」 |
| 憑證版本 | 平台記錄的現行憑證識別（版本號或 `jti`），供驗證比對與問題排查 |
| 有效期限 | **不設期限**（v07 定案）；憑證一經簽發長期有效 |

#### 操作

  - **產生憑證：** 憑證於此區塊產生，**不隨帳號建立自動產生**。產生後**完整顯示一次**，畫面須提供**複製按鈕**並**允許換行完整顯示**（JWT 字串長達數百字元，不可截斷或塞進單行不可捲動的欄位）；關閉後只看得到遮罩
  - **重置憑證：** 二次確認後重新簽發，舊憑證立即失效，畫面同樣完整顯示一次

> ⚠️ 重置憑證會讓機台**立即無法運作**，必須由現場人員把新憑證寫入機台後才會恢復。非必要不要重置，重置前請先與現場確認。

#### 規則

| 項目 | 規則 |
| ---- | ---- |
| 憑證唯一性 | 一台機台同時只有**一組**有效憑證；重置後舊憑證立即失效 |
| 重置即失效的保證 | JWT 本身無法被收回，**必須由平台端保證**：驗證憑證時除簽章外，須比對該機台**目前有效的憑證識別**（如 `jti` 或憑證版本號），舊憑證即使簽章仍有效也一律拒絕。⚠️ **只驗簽章不符合規格** |
| 一次性顯示 | 產生與重置當下各完整顯示一次，之後僅能看到遮罩；遺失以重置處理 |
| 有效期限 | **不設有效期限**（v07 定案）：設期限就必須定義到期前的換發流程，現場逐台重寫憑證成本過高；憑證長期有效，**僅靠「重置憑證」使舊憑證失效** |

相依：API 的憑證附帶方式與驗證流程屬開發包③（`機台金流與場次_spec_v01.md` 附錄）。

### 四、場館設定的洗分門檻（改於機台端設定）

**功能路徑：** 後台管理員系統 \> 站台列表 \> 場館設定（站台類型為「機台」時顯示）

#### 功能說明

洗分門檻是洗分的**計算單位**，於**機台端設定**（同場館各機台可設不同值），隨每筆洗分請求送至平台；**平台計算一律採請求中的 `throshold`**。**後台不實作門檻設定、前台不顯示門檻。**

#### 場館設定欄位（本包相關）

| 欄位 | 說明 |
| ---- | ---- |
| 場館幣別 | 唯讀，自動顯示所屬主站台的核心貨幣 |
| 額度上限 | 全場館共用的入金總額度；作用範圍為該站台自身、不含子站台 |
| 場次逾時時間 | 場次自動結束的閒置時間 |
| 日結時間 | 場館日結報表的結算時點 |

> ⚠️ 場館設定**沒有**「洗分／出金最低門檻」欄位（`站台列表_spec_v04.md` 起移除）。門檻於機台端設定，後台不設。

#### 洗分的門檻計算

| 規則 | 說明 |
| ---- | ---- |
| 採用值 | 一律採洗分請求隨附的 `throshold`；廠商保證每筆請求必帶（正值或 0、不會為負） |
| `throshold = 0` | 表示洗出**全部餘額**、不做取整 |
| `throshold > 0` | 以門檻為單位捨去計算核可金額；**不足一個門檻單位的餘數繼續留在機台帳號上，不會被清除** |
| 可洗金額為 0 | 平台拒絕，回覆機台**餘額不足**（見第五節） |
| 規格外的值 | 負值、缺漏、非數值一律**防禦性拒絕**，回 `6-BAD DATA/FORMAT` |

> 📖 範例（餘額 321）：門檻 100 → 核可 300、餘數 21 留在機台上；門檻 0 → 核可 321、餘額歸 0。

#### 出金

出金**一律清空餘額**、**不套門檻**、**無餘數**；`req-cashout` 的金額參數必為機台當前顯示的全部餘額。

相依：洗分與出金的完整流程與 API 屬開發包③；場館設定欄位屬開發包②（`站台列表_spec_v04.md`，已進版）。

### 五、交易紀錄的兩項欄位規則

**功能路徑：** 各式報表 \> 交易紀錄查詢（機台視角擴充）

#### 場次編號欄位

與線上會員**共用的頁面**（交易紀錄查詢、注單查詢）的「場次編號」欄位，**線上帳號的資料一律顯示「—」**，不留空白、不顯示 0 或 null。機台帳號顯示該筆交易所屬的場次編號。

#### 餘額不足不寫入交易紀錄

洗分或出金因餘額不足被拒絕時，**不寫入交易紀錄**，平台僅回覆機台狀態碼 `1-NO CREDITS`。

| 項目 | 說明 |
| ---- | ---- |
| 適用情形 | 洗分可洗金額為 0（**含以門檻捨去後為 0**），或出金時餘額為 0——屬**正常情形**，不是異常 |
| 交易狀態 | 「未成立」的定義**不包含餘額不足**；其餘拒絕原因才留下「未成立」紀錄並記下原因 |
| 未成立原因對照表 | **不含**餘額不足一列 |

相依：交易狀態流轉與「交易不成立的原因」對照表屬開發包③；列表欄位與篩選器屬開發包④（`機台交易紀錄_spec_v01.md`）。

### 六、場館日結報表的場次數與計價幣別

**功能路徑：** 各式報表 \> 場館日結報表

#### 場次數

依報表的**統計維度**分兩種算法：

| 統計維度 | 場次數的定義 |
| ------- | ----------- |
| 依機台明細 | 該機台當日的場次數 |
| 依場館彙總 | 該場館**所有機台帳號**當日場次數的**加總** |

> 場館彙總不是去重後的場次數，也不是機台數。

#### 計價幣別

場次資訊與日結報表的**有效投注額與損益，一律以主站台核心貨幣計算**（機台場館即 TWD），**不換算 USDT**、不涉及匯率換算。

相依：報表的完整欄位與匯出屬開發包⑤（`場館日結報表_spec_v01.md`）；場次資訊屬開發包③。

### 七、入金額度上限的判定與預留（純後端）

**功能路徑：** 無後台畫面，屬機台對接 API 的平台側邏輯

#### 功能說明

入金的額度上限於**請求階段 `req-cashin`** 判定，並在同一時點把該筆金額**預留**起來；判定與預留在**場館鎖**內逐筆序列化執行，開分共用同一把鎖。`end-cashin` **不再判定額度**，只做入帳並把預留轉為實際分數餘額。

#### 為什麼一定要「預留」

檢查點與累計點不在同一階段就會有缺口：額度檢查在 `req-cashin`，但分數餘額要到 `end-cashin` 才增加，而規格允許**同帳號多筆入金 PENDING 併存**。若 `req-cashin` 只檢查、不佔用額度，多筆 PENDING 會各自通過檢查、合計卻超過上限。

**把金額預留起來**（判定基準＝全場館分數餘額合計 ＋ 已預留未入帳金額 ＋ 本筆），下一筆請求看到的已用額度就已含前一筆，超額會在**紙鈔捲入錢箱之前**被擋下、機台直接退鈔——不會出現「錢已進錢箱才發現超額」的情況。

> 📖 開分（`CreditIn`）是單階段、檢查完立刻入帳，本來就沒有這個缺口；但它必須與入金的預留**共用同一把場館鎖**，且判定基準同樣要含已預留未入帳的入金金額。

> 📖 範例（額度上限 $50,000、目前已用 $49,000）：入金 A $800 送出 `req-cashin`，取得場館鎖，49,000 ＋ 0 ＋ 800 ≤ 50,000 → 建立 PENDING 並預留 800；入金 B $600 送出 `req-cashin`，取得鎖後判定 49,000 ＋ **800（A 的預留）** ＋ 600 = 50,400 > 50,000 → 回 `1-OVER LIMIT`、不建立 PENDING、**機台直接退鈔**，紙鈔不會進錢箱。

#### 預留額度的釋放

預留與釋放必須成對，漏掉任一條路徑額度就會被永久佔用：

| 情況 | 處理 |
| ---- | ---- |
| 入帳成功（`end-cashin` 完成） | 預留轉為實際分數餘額 |
| PENDING 逾時（24 小時） | 由排程關閉該筆時釋放預留 |
| Admin／站長手動取消待確認入金 | 於交易紀錄取消當下立即釋放預留 |

#### 超限時的處置

於 `req-cashin` 回 `1-OVER LIMIT`、不建立 PENDING、不預留；機台直接退鈔，**不涉及退現**。

相依：入金的完整流程與 API 屬開發包③（`機台金流與場次_spec_v01.md`）。

### 相關業務規則（自正本摘錄）

| 項目 | 規則 |
| ---- | ---- |
| 核心貨幣 | 主站台層級的設定，底下所有子站台一律繼承、不可各自指定；線上為 USDT、機台為 TWD。**主站台建立後不可修改**（v07 定案），比照站台類型永久鎖定、編輯視窗唯讀。⚠️ **實作不得將幣別寫死**，清單須可擴充 |
| 洗分門檻採用值 | 平台計算一律採洗分請求隨附的 `throshold`；後台不設門檻、前台不顯示門檻 |
| 餘數保留 | 洗分不足一個門檻單位的餘數繼續留在機台帳號上，不會被清除；出金不套門檻、一律清空餘額 |
| 憑證唯一性 | 一台機台同時只有一組有效憑證；重置即失效須由平台端比對現行憑證識別保證，不能只驗簽章 |
| 交易核實 | 洗分與出金的核實一律於 帳務管理 \>「洗分出金核實」頁執行；交易紀錄頁的核實狀態欄位唯讀 |
