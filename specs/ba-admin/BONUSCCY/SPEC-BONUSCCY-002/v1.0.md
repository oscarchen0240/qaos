# 18 紅利（彩金）幣別盤點

## 一句話

**除了「彩金活動」與「遊戲商 JACKPOT／促銷派彩」，其他紅利一律發「站台系統幣別」。**

玩家拿哪個錢包下注、用什麼幣別存款，都不影響紅利發出來的幣別。

---

## 每一種紅利發什麼幣別

| 紅利                         | 發放幣別                     | 說明                                                                    |
| :--------------------------- | :--------------------------- | :---------------------------------------------------------------------- |
| **返水**                     | 站台系統幣別                 | 計算基礎（有效投注）本來就已換算成系統幣別，兩邊一致                    |
| **代理佣金**                 | 站台系統幣別                 |                                                                         |
| **推薦獎勵**、**推薦註冊金** | 站台系統幣別                 | 註冊金進「收款人所屬站台」的幣別                                        |
| **每日簽到、累積簽到**       | 站台系統幣別                 | ⚠️ 簽到的**道具獎勵不是錢**，不進錢包、沒有幣別                         |
| **首存／次存活動**           | 站台系統幣別                 | ⚠️ 活動設定裡的「幣種」是**選這個活動吃哪一條金流通道**，不是選發放幣別 |
| **累積存款活動**             | 站台系統幣別                 |                                                                         |
| **彩金活動**                 | **後台建活動時自己填的幣別** | 全站唯一可以自己選發放幣別的紅利                                        |
| **遊戲商 JACKPOT／促銷派彩** | **玩家該筆遊戲的錢包幣別**   | 由遊戲幣別依匯率換算後入帳（PP、AWC、SABA 等）                          |

> **2026-09-02 與 PM 確認**：彩金**依後台建活動時選的幣別，送進玩家對應幣別的錢包**。

---

## 人工存款

**人工存款不會進任何活動與累積統計。** 它只做兩件事：把錢加進錢包、寫一筆交易紀錄。

| 項目                               | 有沒有影響                                                                                    |
| :--------------------------------- | :-------------------------------------------------------------------------------------------- |
| 錢進玩家錢包                       | ✅ **有**。後台可指定幣別，沒指定就用站台系統幣別；玩家原本沒有那個幣別的錢包也會自動出現一列 |
| 稽核流水（打碼量）                 | ✅ **有**，依後台填的稽核倍數                                                                 |
| 首存／次存活動                     | ❌ **不觸發**，不算首儲、也不會配到任何存款活動                                               |
| 累積存款活動                       | ❌ **不累積**                                                                                 |
| 簽到活動的「有效會員」門檻         | ❌ **不計入**                                                                                 |
| 玩家累積儲值統計（VIP 等級的依據） | ❌ **不計入**，所以也不會推進 VIP 等級                                                        |

> **2026-09-02 確認**：後台人工存款目前走 v4，**不會計入累積儲值**，對 VIP 等級也沒有影響。
> （舊版 v1 的 API 還在線上、那支會計入，但後台沒有在用。）

## 要注意的事

### 存款通道的幣別要跟站台系統幣別一致

**一致的話（例如機台站台系統幣別 TWD、機台通道也是 TWD）→ 全部正確。**
不一致時（例如 USDT 站台收到一筆 1000 TWD 的存款）會變成：

| 經過哪裡                            | 結果                                                                   |
| :---------------------------------- | :--------------------------------------------------------------------- |
| 錢進玩家錢包                        | ✅ **正確**，進 TWD 錢包，玩家切換錢包看得到                           |
| **累積存款活動的門檻**              | ❌ **1000 TWD 被當成 1000 USDT 累加**，門檻提早達標                    |
| **簽到活動的「有效會員」門檻**      | ❌ 同上，玩家提早變成有效會員                                          |
| **玩家累積存款統計**（VIP、排行榜） | ❌ 同上，數字被灌大                                                    |
| **首存／次存活動**                  | ❌ 沒幫那條通道建活動就**完全不發**；建了活動則**金額被灌大**（見下）  |
| 後台營運日報的總入金                | ✅ 只算系統幣別的存款，**數字變小是預期不是 bug**（見 `16` 的 `1-10`） |
| **後台人工存款**                    | ✅ **完全不觸發上面這些**，打任何幣別都不會有問題                      |

> 上面四個 ❌ 只有在「真的有一筆非系統幣別的存款進來」時才會發生。

#### 本次不調整的理由

**現在還沒有非系統幣別的存款會進來** —— 機台的開分／入金要等實體機台的交易寫入上線
才會真的有交易，線上站台也不會用非系統幣別的通道存款，所以這幾條目前都是死路。
現在動它得引進匯率換算，等於在沒有實際案例的情況下多開一個出錯點。

**等 TWD 存款正式進來之後，再依實際狀況一併評估與調整。**

### 要改的話，只加匯率換算就會正常嗎

**不會，四個 ❌ 只有一個是「乘個匯率就好」。**

| 上面的 ❌                | 只加換算夠嗎                                                                                                       |
| :----------------------- | :----------------------------------------------------------------------------------------------------------------- |
| 首存／次存活動的發放金額 | ✅ **夠**，把算出來的獎勵從通道幣別換成核心貨幣就對了                                                              |
| 累積存款活動門檻         | ❌ 不夠。它是「每筆存款累加」的欄位，要決定**用哪個時點的匯率**，而且**換算後的值要存下來**，否則之後對不了帳      |
| 玩家累積存款統計（VIP）  | ❌ 同上，而且這張表已經有歷史值                                                                                    |
| 簽到「有效會員」門檻     | ❌ 不夠。它直接在 SQL 跑總和，**沒有幣別欄位可以濾、也沒有換算後的欄位可以加總**，要加欄位或改成只算核心貨幣的存款 |

而且加了換算會帶進**新的**問題：

- **門檻的幣別語意要先定案** —— 活動是 per 通道建的，後台欄位上沒有標幣別，
  要對齊 UI，否則營運照 TWD 填、程式照核心貨幣比。
- **報表口徑要一起改** —— 日報現在是「只算核心貨幣的存款」，改成換算入帳就得跟著改。

所以真的要做，是「換算時點 → 存欄位 → 匯率 0 的防線 → 後台 UI 標幣別 → 報表口徑」
五件事一起做的一個小專案，不是加一行換算。

> 一個對我們有利的點：**現在那幾張累加表還是乾淨的**（沒有非核心貨幣的存款進來過），
> 所以之後要改不用處理歷史混幣資料；但等 TWD 存款開始進來之後才改，就得先清一次。

---

### 2026-09-02 與 PM 確認：存款活動只能發核心貨幣

以現在的結構，**存款活動的獎勵只能發站台核心貨幣**，所以活動本身也要用核心貨幣來訂，
例如「存 100 USD 送 30 USD」。玩家用 TWD 存款時，要**換算成核心貨幣之後再比門檻**
（以 TWD:USD = 30:1 為例）：

| 玩家存入 | 換算成 USD | 結果                         |
| :------- | :--------- | :--------------------------- |
| 2100 TWD | 70 USD     | 未達 100 USD，**拿不到**優惠 |
| 3000 TWD | 100 USD    | 達標，**送 30 USD**          |

⚠️ **現行程式還沒有這段換算** —— 目前是直接拿存款金額的數字去比門檻，
所以現況會變成「存 2100 TWD 也算達標、一樣送 30」。
這個落差**等 TWD 存款通道進來時一併調整**。
