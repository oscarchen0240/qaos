# CLR-SITELIST-016：v0.6 原文與已落地的 CLR 定案直接牴觸，本 RM 不自行裁定。v0.6（版本日期 2026-09-04）§角色與權限「子站台：刪除｜可操作｜可操作」、§列表欄位「操作｜編輯、刪除」、§操作/刪除站台（確認彈窗、二次確認、不可復原）、§業務規則/刪除確認，皆定義管理員與站長可刪除管轄範圍內的子站台（僅自身站台與根站台不可刪除）；CLR-SITELIST-008／009（2026-09-14，PM 與後端共同確認，晚於 v0.6 版本日期）定案「任何類型的站台皆不提供刪除操作，前後端皆拒絕，只能暫停／關閉」，原因是刪除會影響站台樹狀結構。v0.6 取自 ba-spec main 2026-09-29 快照仍保留刪除敘述，QA 增補草稿要求移除該節亦未合入正本，無法判斷是 spec 未同步 CLR，還是產品方向已改回可刪除。

## 背景
REQ-SITELIST-022：子站台能否刪除，v0.6 原文與已落地 CLR 互相牴觸，待 RESOLVE_AMBIGUITY 裁定：(A) v0.6 原文——管理員與站長可刪除管轄範圍內的子站台；列表操作欄含「刪除」，點擊後顯示確認彈窗列出站台名稱與代碼，二次確認後執行，操作不可復原；(B) CLR-SITELIST-008／009（2026-09-14 PM／後端共同確認）——任何類型（線上、機台）的站台皆不提供刪除操作，前端無入口、後端 API 拒絕刪除請求，只能暫停／關閉。兩者僅在「自身所屬站台不可刪除」（REQ-SITELIST-035）與「根站台不可刪除」（REQ-SITELIST-031）一致。未裁定前 A、B 兩側的 AC 皆不得作為 Test Case 依據。

## 可能的解讀（請勾選或補充）
- [ ] 以 CLR-SITELIST-008／009 為準：任何站台皆不提供刪除（前端無入口、後端拒絕），v0.6 的「子站台：刪除」列、§操作/刪除站台與刪除確認規則為待修正的錯誤敘述
- [ ] 以 v0.6 原文為準：管理員與站長可刪除管轄範圍內的子站台（自身站台與根站台除外），確認彈窗二次確認後執行、不可復原；CLR-SITELIST-008／009 視為被取代，並須補定義有子站台時的處理（REQ-SITELIST-023）
- [ ] 部分採用：僅特定條件可刪除（例如無子站台、未曾開通），其餘不可刪除，需 PM 補定義條件
