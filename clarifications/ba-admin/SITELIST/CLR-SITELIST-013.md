# CLR-SITELIST-013：REQ-SITELIST-035 不符合時系統應如何反應？（Spec 未定義拒絕行為）

- 產品 / 功能：ba-admin / SITELIST
- 規格：SPEC-SITELIST-001 v0.6  §§角色與權限/自身站台三列 + §操作/編輯站台/上層站台、狀態 + §業務規則與驗證/管理員的自身站台限制
- 相關需求：REQ-SITELIST-035
- 提出者：agent-spec-analyst（2026-10-02）
- 狀態：OPEN

## 背景
管理員對自身所屬站台有三項限制：(1) 不可修改自身站台的上層站台（編輯視窗唯讀）；(2) 不可刪除自身站台；(3) 不可將自身站台切換為「開通」（含由「更新待審」切回），可切「暫停」「關閉」。這三項須由上層站台的管理員執行（其中「刪除由上層站台的管理員執行」屬 REQ-SITELIST-022 衝突範圍，本條不據此認定刪除存在）。名稱、網域、模板、場館設定等其餘欄位可自行編輯；對子站台無此限制。站長對自身站台同樣不可修改上層、不可刪除、不可切為開通。根站台 admin 無上層，三項限制對其不成立，改適用根站台保護規則。
v0.6 只定義前端行為（上層站台唯讀、開通不可選／不可切回），未定義管理員或站長繞過前端、以 API 對自身站台修改上層站台、刪除或切為開通時後端是否拒絕（§根站台的「後端一併實作」只針對根站台保護規則）
