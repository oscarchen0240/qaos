# CLR-SITELIST-009：CLR-SITELIST-008 回答「任何類型皆不可刪除」，這是指前端限制、後端也限制、還是回答有誤（可能指別的情境）？

- 產品 / 功能：ba-admin / SITELIST
- 規格：SPEC-SITELIST-001 v0.4
- 相關需求：REQ-SITELIST-023
- 提出者：oscarchen@blockaction.tech（2026-09-13）
- 狀態：APPLIED

## 背景
Oscar 直接觀察：目前前端刪除按鈕對兩種類型皆為 disable。但後端是否也擋下刪除、或其實仍可刪除，尚未與後端工程師確認；PM 那邊也會重新核對 CLR-008 這句話的確切意思。在此確認之前，不應把「任何類型皆不可刪除」當定論寫進正式 Test Case（會直接牴觸 spec.md v0.4「刪除站台可正常執行」的原文，屬於矛盾而非單純空白，風險層級較高——見 Validator 對 TC-SITELIST-042 v2 的 FAIL 意見）。

## 可能的解讀（請勾選或補充）
- [ ] 僅前端限制（後端 API 仍可刪除，屬前端尚未實作或刻意先擋 UI）
- [ ] 前後端皆限制（後端也會拒絕刪除請求）
- [ ] CLR-008 的回答有誤／指的是其他情境，需重新確認

## 若未回答的影響
TC-SITELIST-042 的修訂（RUN-20260914-003）暫緩至此單有回覆；REQ-022/023 在此之前沒有可用的 ACTIVE 覆蓋

## PM 回覆
已確認：前端與後端皆拒絕刪除站台，不論線上或機台類型皆同（與 CLR-SITELIST-008 的結論一致，非誤答）。原因是刪除站台會影響站台樹狀結構（子站台歸屬、上下層關係），故刻意不提供刪除功能，僅能暫停／關閉（停用）。spec.md v0.4 原文「刪除站台可正常執行」一節與此結論牴觸，屬 spec 需修正的錯誤敘述，非目前產品行為。
