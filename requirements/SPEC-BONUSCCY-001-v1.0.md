## REQ-BONUSCCY-001 注單查詢/明細頁的金額欄位以站台核心貨幣顯示

**需求**：機台站台（TWD核心貨幣）的注單三層金額（game_bet_log → wallet_reference → system_wallet_reference）第三層的幣別與換算已改依站台核心貨幣；後台注單查詢/明細頁的金額欄位應對應顯示核心貨幣，不是寫死的 USDT

- 類型 functional · 行為 success · 風險 medium · 狀態 ACTIVE
- spec 位置：§實際被改到的地方（表格第2項：注單三層金額）　引句：「注單三層金額 | game_bet_log → …_wallet_reference → …_system_wallet_reference，第三層的幣別與換算改依站台核心貨幣」
- 驗收條件：
  - 001：給定 一筆機台（TWD核心貨幣站台）的注單；當 檢視後台注單查詢/明細頁的金額欄位；則 金額以站台核心貨幣（TWD）顯示，不是寫死顯示 USDT 或其換算值
- 不符合時系統怎麼做：spec 有寫——規則已明確定義；日結報表層級的核心貨幣計算已由 SPEC-DAILYREPORT-001 REQ-013 驗證，本條測的是注單查詢/明細頁本身，過去未被任何 spec 測過
- 對應 TC：TC-BONUSCCY-001 v1

## REQ-BONUSCCY-002 會員列表與 Dashboard 總會員數正確涵蓋機台（TWD）站台會員

**需求**：後台查詢頁（會員列表、Dashboard 總會員數等）原本的 JOIN 條件比對寫死的 USDT 常數，已改為依站台核心貨幣查詢；機台（TWD核心貨幣）站台的會員應正確被涵蓋，不因舊有寫死的比對條件而被排除或漏計

- 類型 functional · 行為 success · 風險 high · 狀態 ACTIVE
- spec 位置：§實際被改到的地方（表格第3項：後台查詢）　引句：「後台查詢 | 注單列表與明細、返水明細、營運日報、會員列表、Dashboard 總會員數 —— 這些的 JOIN 條件原本比對常數」
- 驗收條件：
  - 002：給定 機台（TWD核心貨幣）站台底下已有會員；當 檢視 Dashboard 總會員數統計；則 這些會員正確計入總會員數，不因原本寫死 USDT 的 JOIN 條件而被排除
  - 003：給定 站台切換選單切至機台（TWD）站台；當 檢視會員列表；則 正確列出該站台會員，不因幣別相關的查詢條件而遺漏資料
- 不符合時系統怎麼做：spec 有寫——規則已明確定義，屬於這次架構變更的核心回歸風險——若 JOIN 條件沒改乾淨，機台站台的資料會在報表/列表裡悄悄消失而不是報錯，風險標 high
- 對應 TC：TC-BONUSCCY-004 v1, TC-BONUSCCY-002 v1, TC-BONUSCCY-003 v1

## REQ-BONUSCCY-003 人工存入／人工提出未指定幣別時，預設寫入站台核心貨幣

**需求**：人工出入金四支功能原本沒有明確寫入幣別（靠資料表 DEFAULT 或寫死 USDT），已改為取站台核心貨幣；對機台（TWD核心貨幣）帳號執行人工存入/提出且未指定幣別時，應寫入/扣除該站台的核心貨幣（TWD）

- 類型 functional · 行為 success · 風險 high · 狀態 ACTIVE
- spec 位置：§實際被改到的地方（表格第6項：人工出入金）　引句：「人工出入金 | 四支原本沒有明確寫入幣別（靠資料表 DEFAULT 或填死 USDT），改成取核心貨幣」
- 驗收條件：
  - 004：給定 對一個機台（TWD核心貨幣）帳號執行人工存入，未指定幣別；當 檢視入帳結果；則 金額寫入該站台核心貨幣（TWD）錢包，不是寫死的 USDT
  - 005：給定 對同一機台帳號執行人工提出，未指定幣別；當 檢視扣款結果；則 從該站台核心貨幣（TWD）錢包扣除，不是寫死的 USDT
- 不符合時系統怎麼做：spec 有寫——規則已明確定義，直接關係金流正確性——若預設幣別沒改乾淨，錢會進錯錢包或找不到對應餘額扣款
- 對應 TC：TC-BONUSCCY-005 v1, TC-BONUSCCY-006 v1, TC-BONUSCCY-007 v1

## REQ-BONUSCCY-004 核心貨幣所對應的錢包幣別可停用作止損用途；停用後入金/出金/開分/洗分四項操作皆須被阻擋

**需求**：核心貨幣本身只能從資料庫層級關閉，站台使用者無法在鏈上錢包管理直接關閉核心貨幣這個抽象設定；鏈上錢包管理中「停用」某幣別（例如TWD）這個操作，是停用該站台可用的一筆錢包幣別紀錄（wallet_currency），此功能刻意保留，用途是資金池出問題等異常狀況時讓機台即時止損。當核心貨幣所對應的那筆錢包幣別被停用後，入金、出金、開分、洗分四項操作皆應被系統阻擋，防止資金繼續流入或流出一個已停用的幣別（已由 Oscar/PM 2026-09-15 確認，並於 2026-09-15 進一步澄清「核心貨幣」與「錢包幣別停用」的概念區分）

- 類型 constraint · 行為 rejection · 風險 medium · 狀態 ACTIVE
- spec 位置：§一句話（限制段落）　引句：「一個限制：站台的系統幣別必須是啟用中的錢包幣別之一（wallet_currency.enabled = 1），否則獎勵會發到玩家看不到的錢包；補充（2026-09-15 PM確認）：核心貨幣所對應的錢包幣別可停用作即時止損用途，停用後入金/出金/開分/洗分四項操作皆須被阻擋（2026-09-15進一步澄清：核心貨幣本身只能從DB關閉，鏈上錢包管理停用的是該幣別的wallet_currency紀錄，非核心貨幣設定本身）」
- 驗收條件：
  - 006：給定 站台核心貨幣對應的錢包幣別（例如TWD）已被停用；當 嘗試對該站台帳號執行入金；則 系統阻擋，不允許入金
  - 022：給定 站台核心貨幣對應的錢包幣別已被停用；當 嘗試對該站台帳號執行出金；則 系統阻擋，不允許出金
  - 023：給定 站台核心貨幣對應的錢包幣別已被停用；當 嘗試對該站台帳號執行開分；則 系統阻擋，不允許開分
  - 024：給定 站台核心貨幣對應的錢包幣別已被停用；當 嘗試對該站台帳號執行洗分；則 系統阻擋，不允許洗分
- 不符合時系統怎麼做：spec 有寫——規則已由 PM 2026-09-15 明確補充確認：停用本身允許（止損用途），但停用後四項操作皆須阻擋；具體錯誤訊息文案未給，只測是否被阻擋
- ✅ PM 回答（CLR-BONUSCCY-002）：1. 可以停用核心貨幣——這是刻意設計，用途是當資金池出問題時可以即時止損。2. 當鏈上錢包的核心貨幣被關閉時，入金、出金、開分、洗分四個操作都需要被阻擋，不是只擋開分/入金兩項。
- 對應 TC：TC-BONUSCCY-008 v1, TC-BONUSCCY-008 v2, TC-BONUSCCY-008 v3, TC-BONUSCCY-029 v1, TC-BONUSCCY-030 v1, TC-BONUSCCY-031 v1
