## REQ-BONUSCCY-011 存款原始金額正確進玩家錢包，不受「原始金額/核心貨幣金額」欄位拆分影響

**需求**：存款金額拆成「原始金額」（進錢包、算流水倍數、算手續費）與「核心貨幣金額」（比活動門檻、累積儲值統計、有效會員）兩個欄位後，玩家存多少錢，進錢包的金額與幣別仍應正確——這是本次部署最重要的回歸點

- 類型 functional · 行為 success · 風險 high · 狀態 ACTIVE
- spec 位置：§改了什麼／①存款金額拆成兩個 + §這次能測什麼／T2　引句：「原始金額 | 玩家實際存的錢，玩家看到的幣別 | 進錢包、算流水倍數、算手續費 ｜ T2 入金金額進錢包正確：存多少就進多少，幣別正確。這是最重要的回歸點」
- 驗收條件：
  - 017：給定 玩家於線上站台完成一筆系統存款（非人工存款）；當 檢視入帳結果；則 存入多少金額就進玩家錢包多少金額，幣別與存款當下一致，不因新拆出的「原始金額」欄位而算錯或漏算
- 不符合時系統怎麼做：spec 有寫——規則已明確定義，且 spec.md 自己點名是本次部署最重要的回歸點
- 對應 TC：（尚無）

## REQ-BONUSCCY-012 流水倍數與手續費以實際存入金額（原始金額）為基數計算

**需求**：存款後的「提領所需有效投注額」（流水門檻）與手續費，應以玩家實際存入的原始金額為基數計算，不是核心貨幣金額（換算後的比較用數字）

- 類型 functional · 行為 success · 風險 medium · 狀態 ACTIVE
- spec 位置：§改了什麼／①存款金額拆成兩個 + §這次能測什麼／T3　引句：「原始金額 | … | 進錢包、算流水倍數、算手續費 ｜ T3 流水倍數與手續費的基數正確：存款後的「提領所需有效投注額」要以實際存入金額為基數算，不是別的數字」
- 驗收條件：
  - 018：給定 玩家完成一筆系統存款；當 檢視存款後的提領所需有效投注額（流水門檻）與手續費計算結果；則 皆以玩家實際存入的原始金額為基數計算，不是核心貨幣金額或其他換算後的數字
- 不符合時系統怎麼做：spec 有寫——規則已明確定義
- 對應 TC：（尚無）

## REQ-BONUSCCY-013 簽到活動前台進度條與後台判定一致，皆讀取正確的入帳資料表

**需求**：簽到活動「有效會員」的判定，前台進度條與後台判定改為皆讀取 deposit_log_v2（入帳成功的存款都在裡面），不再是前後台各自讀不同的舊表；前台進度條應正確顯示進度並與後台判定一致，不再永遠顯示 0

- 類型 functional · 行為 success · 風險 medium · 狀態 ACTIVE
- spec 位置：§改了什麼／②簽到活動的「有效會員」改讀正確的表 + §這次能測什麼／T1　引句：「後台判定：以前讀區塊鏈明細表，現在讀 deposit_log_v2（入帳成功的都在裡面）；前台進度條：以前讀另一張更舊的區塊鏈表，現在同上、與後台一致 ｜ T1 前台進度條會動、且與後台一致：前台簽到頁的有效會員進度條，數字應該跟後台判定的累積金額一致。以前前台永遠顯示 0」
- 驗收條件：
  - 019：給定 玩家有已入帳成功的存款記錄，尚未達到有效會員門檻；當 檢視前台簽到頁的有效會員進度條；則 進度條正確顯示累積金額，與後台判定的累積金額一致，不再是以前那樣永遠顯示 0
  - 020：給定 玩家的累積存款達到有效會員門檻；當 開啟一次前台簽到頁；則 進度條達標並直接寫入有效會員狀態，與後台最終判定結果一致
- 不符合時系統怎麼做：spec 有寫——規則已明確定義；spec 特別提醒這是唯一會讓數字變的改動，部署後玩家只要開一次簽到頁就會用新口徑重算，本來已達標的玩家會立刻變成有效會員——這是修正不是錯誤，但要驗證這個變化确实如預期發生
- 對應 TC：（尚無）

## REQ-BONUSCCY-014 簽到活動「有效會員每月重置」機制，跨月後進度正確歸零重算

**需求**：簽到活動若開啟「有效會員每月重置」設定，跨月後有效會員的累積進度應正確歸零並重新開始計算，不受本次讀取資料表來源變更（改讀 deposit_log_v2）影響

- 類型 functional · 行為 success · 風險 medium · 狀態 ACTIVE
- spec 位置：§這次能測什麼／T5　引句：「T5 每月重置仍正常：簽到活動若開了「有效會員每月重置」，跨月後進度應歸零重算」

  - 021：給定 簽到活動已開啟「有效會員每月重置」設定，玩家上個月的累積進度已達有效會員門檻；當 跨月後檢視該玩家本月的有效會員進度；則 進度正確歸零，重新從 0 開始累積計算，不因改讀 deposit_log_v2 而受影響（例如不會誤讀到上個月已計入歸零前的舊資料）
- 不符合時系統怎麼做：spec 有寫——規則已明確定義
