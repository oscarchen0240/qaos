問題詳述

REQ-BONUSCCY-004 已由 PM 2026-09-15 明確確認：核心貨幣停用是刻意設計的即時止損手段，停用後入金/出金/開分/洗分四項操作皆須被系統阻擋。 實測發現出金與洗分在核心貨幣已停用的情況下仍可正常完成扣分，止損機制形同虛設。入金/開分雖目前失敗，但回應的是「7-OUT OF SERVICE（服務不可用 DB/Redis/下游異常）」這種下游基礎設施錯誤，而非「核心貨幣已停用」的明確業務拒絕——目前看似被擋，實際上可能只是下游異常的巧合，並非系統刻意的止損邏輯。四項操作背後應是同一個判斷點（核心貨幣 wallet_currency.enabled 狀態），目前顯然缺乏統一檢查。

預期結果 / 實際結果

預期結果
四項操作（入金、出金、開分、洗分）皆應被系統阻擋，不應完成入帳/扣分。
實際結果
出金、洗分皆回 0-OK 成功完成扣分；入金、開分回 7-OUT OF SERVICE（非明確業務拒絕）。

複製步驟

  1. 登入機台版後台，至鏈上錢包管理，將該站台核心貨幣 TWD 對應的兩筆錢包幣別紀錄狀態改為停用
  2. 切到機台版前台，依序嘗試：入金（投紙鈔，觸發 req-cashin → end-cashin）、出金（按 CASHOUT 鍵，觸發 req-cashout → end-cashout）、開分（店員收現金加分，觸發 req-keyin）、洗分（觸發 req-keyout）
  3. 觀察四項操作各自的系統回應

API URL

req-cashin → end-cashin （入金，兩階段） req-cashout → end-cashout （出金，兩階段） req-keyin （開分，單階段） req-keyout （洗分，單階段）

畫面證據

懷疑方向

後端 cashflow 服務（req-cashin/end-cashin、req-cashout/end-cashout、req-keyin、req-keyout 四支 API）在處理交易前，未檢查該站台核心貨幣對應的 wallet_currency.enabled 狀態；出金/洗分完全遺漏此檢查，入金/開分目前的失敗疑似只是下游服務異常的巧合，非刻意設計的阻擋邏輯。
