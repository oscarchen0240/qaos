後端 req-cashin / end-cashin 的額度上限判定邏輯；以及未成立交易的紀錄寫入邏輯。前端未發現問題。

問題詳述

對機台送出遠超場館額度上限的入金：req-cashin 回 0-OK、建立 PENDING、拿到 TXID——紙鈔已進錢箱；到 end-cashin 確認時才回 1-OVER LIMIT。查詢該機台帳號的交易紀錄，總筆數 0，這筆交易（含 PENDING 曾建立過的痕跡）完全找不到。

① 判定時機錯

依現行 v07 定案（2026-09-04），額度上限應在 req-cashin（第一階段）判定並預留，超額時不建立 PENDING、紙鈔不進錢箱。實際是 end-cashin 才判定——等同執行已被 v07 明文廢除的 v06 舊邏輯。

② 紀錄完全消失

不論判定發生在哪個階段，被額度上限拒絕的交易都該留下「未成立」紀錄。實際上這筆交易在系統裡完全找不到——不是歸類錯誤，是資金軌跡缺失：紙鈔已進錢箱，後台卻毫無紀錄可查。

SPEC-ARCADE-001 v0.7 changelog v07（2026-09-04，最終定案）
入金額度上限的判定與預留移至 req-cashin（原 v06 為「最終判定於 end-cashin」）：請求階段取場館鎖……通過才建 PENDING 並預留額度；end-cashin 不再判定額度，超額因此在紙鈔捲入錢箱前就被擋下，原「入帳階段超限處置待定案」一條移除
SPEC-CASHFLOW-001 v0.1 · AC-CASHFLOW-0302
交易因額度上限或其他原因被拒絕，有留下「未成立」的交易紀錄，可查得拒絕原因

預期結果 / 實際結果

預期　① req-cashin 即擋下超額入金、不建 PENDING；② 不論哪個階段拒絕，都應留下「未成立」交易紀錄、可查拒絕原因。
實際　req-cashin 成功建 PENDING（紙鈔已收）；end-cashin 才拒絕；交易紀錄總筆數 0，查無此筆。
  • EVD-0073對照組：洗分餘額不足回 1-NO CREDITS（spec 明文允許的例外，行為正確）
  • EVD-0074req-cashin 0-OK 建 PENDING（TXID 1af58cd7-7170-4ee5-a9b0-ad3ef6bb3910），end-cashin 才回 1-OVER LIMIT
  • EVD-0075交易紀錄查詢機台帳號 ACAA00417，其餘欄位全空白，總筆數 0

複製步驟

  1. 對 Arcade 場館某機台以開發工具送出 req-cashin，金額為足以使全場館分數餘額合計超過額度上限的極大值
  2. 檢視 req-cashin 回應（預期應直接 1-OVER LIMIT；實際回 0-OK 並取得 TXID）
  3. 以同一 TXID 送出 end-cashin，檢視回應（實際為 1-OVER LIMIT）
  4. 進入「各式報表 › 交易紀錄查詢」，以該機台帳號查詢（不設其他篩選）
  5. 檢視搜尋結果總筆數
